## 실제 검증과 남은 확인

환경: Windows, .NET SDK10.0.302 / Desktop runtime8.0.28, Python3.13.15 및 기존 전용 패키지 환경.

```powershell
dotnet build RemoteWork.WinForms/RemoteWork.WinForms.csproj -c Release --no-restore -v minimal
dotnet run --project Tests/ActivityPresence.Tests
.\Tools\HandPresence\.venv\Scripts\python.exe -m unittest discover -s Tools/HandPresence -p 'test_*.py'
.\Tools\HandPresence\.venv\Scripts\python.exe -m py_compile Tools/HandPresence/hand_presence.py Tools/HandPresence/presence_core.py Tools/HandPresence/winforms_bridge.py Tools/HandPresence/test_hand_presence.py Tools/HandPresence/test_winforms_bridge.py
```

- Release 빌드 경고0/오류0. 초기 --no-restore 시 obj가 없어 실패한 뒤 정상 restore/build 완료한 결과. 생성 파일은 Git 제외.
- C# 5시나리오46검증 통과: 실제 UI 메시지 루프·합성 JPEG·카메라 대역, 직원/관리자의 근태 버튼→소유 모달 실제 열기/닫기, 시작/영역 오류/활동·자리비움/지연/복구/손상 JPEG, 중지 후 늦은 결과 무시, 종료 중 중복 시작 차단과 닫기 대기. 실제 Python stdio로 stderr 대량 출력 동시 drain·최신 프레임·Windows QPC 신선도·즉시 중지·비정상 종료·무응답 자식 종료 확인.

## 후속 — 실제 실행 시작 지연 수정

- 사용자 보고: 새 C# 창에서 카메라 연결 지연/최신 영상 대기가 지속. DSHOW→MSMF 변경 후에도 동일. 사용자가 프로그램 전체를 닫았음을 확인한 뒤 수정·빌드.
- 재현: 별도 합성 실행은 정상이었지만 사전 NumPy import가 없는 실제 bridge CLI가 stdin 읽기 스레드 시작 후 OpenCV/NumPy 네이티브 import에서 정지. 진단 스택의 worker는 NumPy 확장 create_module, 제어 스레드는 stdin, main은 queue 대기였다. 내부 DLL 잠금의 구체 원인을 단정하지 않음.
- 변경: bridge main에서 cv2/NumPy를 먼저 초기화하고 제어/작업 스레드를 시작. 모델 준비·카메라 연결·첫 영상 수신/분석 진행을 C#에 표시하고 지연 시 마지막 단계를 유지. 관련9파일 로컬 코드 커밋 `06f3376b040cf0e43e830545dfdfd4511f3e8564`.
- 검증: 새 Python 프로세스의 실제 bridge CLI와 명시적 카메라/모델 대역으로 초기화 회귀 추가. C#5시나리오49검증·Python24개 통과, Release 경고0/오류0·diff 검사 통과. 앞서 기록한46/23을 최신 실행으로 정정하며 과거 결과는 보존.
- 에이전트 환경에서 사용자 선택과 같은 카메라0/DSHOW를 짧게 열기 시도했으나 장치 열기 실패. 수정 뒤 진행/장치 오류가 약1초 내 반환됨 확인. 실제 영상 수신·인식 성공으로 기록하지 않음. 진단에서 이미지 표시/파일 저장/업로드 없음. 사용자 PC의 새 빌드 재실행·실제 영상 확인은 대기.
- 원격 push·PR 갱신·원본 병합·공통 정책 변경 없음. 기존 승인된 로컬 연결 범위 내 오류 수정이며 사용자 ‘보내’ 지시 전 계속 업로드 보류.
