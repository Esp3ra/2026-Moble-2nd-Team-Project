## 변경 전후·영향

종료 정리를 기다리며 취소한 부모 종료 요청을 기억하지 않아, 자식만 닫히고 메인이 남았다. 이제 `FormOwnerClosing` 요청은 정리 중에도 기억하고, 카메라·조도 정리가 모두 끝난 뒤 UI 큐에서 자식을 닫고 해당 부모의 종료를 한 번 이어간다. 일반 모달 닫기는 부모 종료를 요청하지 않는다.

중지·오류·닫기가 겹치면 같은 정리 Task를 기다린다. 새 시작 때만 이를 초기화하여 중복 Stop을 막는다. 기존 Python 자식의 정상 종료/2초 유예/소유 프로세스 트리 강제 종료와 조도 취소 기준은 유지한다. 공통 로그인 만료 처리 자체를 고치지 않고 그 창 수명에 맞게 5번 자식 창을 정리한다.

## 실제 검증

Windows, .NET SDK 10.0.302/Desktop 8.0.28, Python 3.13.15의 기존 전용 가상환경. 최신 원본 alpha를 합친 수정 커밋 `8191b431ca62dc90a9370ca778a9b9ca19ab843d`에서 아래를 실행했다. 산출물은 Git 제외 `work/`에 두어 실행 중인 사용자 프로그램을 종료하거나 덮어쓰지 않았다.

```powershell
dotnet run --project Tests/ActivityPresence.Tests --artifacts-path ./work/member5-pr-validation

dotnet build RemoteWork.WinForms/RemoteWork.WinForms.csproj -c Release --artifacts-path ./work/member5-pr-validation -v minimal
```

- 수정 전 신규 모달 회귀에서 `owner/immediate: owner close resumes exactly once` 실패로 부모 잔류를 재현했다. 수정 후 C# **260검증/11시나리오 통과**. 기존 156검증과 R23-01·30초 판정·stdio·Pi HTTP 회귀를 포함하며 별도 합산하지 않는다.
- 일반 닫기/부모 닫기/자식→부모 즉시·늦은 닫기 × 즉시·지연 정리 8조합. 카메라만 끝나고 조도가 남으면 기다리며, 일반 닫기는 메인을 유지하고 부모 종료는 한 번 재개한다. 중지 중 닫기도 정리를 중복 실행하지 않는다.
- 실제 제품 LoginForm→MainForm→활동 창 + 테스트 소유 loopback HTTP의 합성 로그인·빈 공지·401 응답. 즉시/지연 정리 × 만료 안내 즉시/늦게 닫기 4조합에서 실제 ApiClient의 세션 해제·메인 종료·로그인 화면 복귀가 각각 한 번이다. 테스트 UI 스레드에서 해당 MainForm이 소유한 안내 창만 제어한다. 서버 주소는 테스트 프로세스 메모리에서 복원하며 설정 파일을 쓰지 않는다.
- 응답 없는 실제 Python 대역으로 일반 모달/자식→부모 닫기 2경로를 검사했다. 2초 유예 뒤 소유 자식 종료·조도 해제, 일반 닫기의 부모 유지 확인. PID 임시 파일은 삭제했다.
- Python **30개 통과**, Release **경고 0/오류 0**, diff 검사 통과. 실제 카메라·Pi·사용자 영상·지문·실제 공통 서버·DB는 이번에 사용하지 않았다. loopback 응답은 테스트 대역이며 운영 인증/DB나 실장비 정확도 검증이 아니다.
