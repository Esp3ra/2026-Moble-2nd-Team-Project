# 업무 조회 — 선택 유지·상세 재시도·취소 처리

작성일: 2026-10-17 · [alpha 329d4a3](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/commit/329d4a32ff316ed2ae208a40e5b1ba0f743d958c)

## 문제와 수정 결과

같은 목록의 두 번째 이후 업무를 선택해도 다시 조회하면 첫 업무로 돌아갔다. 상세 오류 뒤의 재시도도 전체 목록과 첫 업무를 다시 호출했다. 공통 클라이언트가 접속을 바꿔 조회를 취소하면 화면 자체 토큰은 미취소일 수 있어 서버 오류로 표시됐다.

- 같은 내 업무/관리 업무·상태 조건의 재조회는 선택 ID를 유지한다. 응답 순서가 바뀌거나 조회가 겹쳐도 최신 목록에 있는 같은 ID를 찾는다. 사라졌으면 현재 첫 행, 빈 목록이면 선택·상세를 초기화한다.
- 범위나 상태를 바꾸면 이전 선택을 가져가지 않는다. 지난 범위의 늦은 응답도 새 선택을 덮지 않는다.
- 상세 실패 시 버튼은 **상세 재시도**가 되며 선택한 업무의 상세만 호출한다. 목록은 유지하고 서버 권한 검사를 새 상세 호출에 맡긴다. 성공 후 버튼은 전체 **다시 조회**로 돌아간다.
- 다른 행·범위·상태·종료로 바뀌면 실패했던 상세의 재시도 대상을 초기화한다.
- **F5는 전체 목록을 다시 조회**한다. 자식 텍스트박스 포커스에서도 동작하며 tooltip/접근성 설명을 제공한다. 상세404 뒤 삭제된 업무를 목록에서 제거할 수 있다.
- 공통 접속 취소는 이전 목록·상세를 비우고 취소로 안내한다. 재시도는 명시적으로 하며 실제401 인증 만료·서버 오류와 구분한다. 교체/선택/종료에 따른 늦은 취소는 현재 화면에 영향을 주지 않는다.

동기 완료되는 취소 대역을 행 선택 이벤트 안에서 처리하면 DataGridView 현재 셀 변경 중 행 제거가 재진입할 수 있었다. 상세 취소에서는 UI 메시지 처리를 한 차례 양보한 뒤 세대/선택/취소 토큰을 재검사하고 화면을 비우도록 수정했다.
