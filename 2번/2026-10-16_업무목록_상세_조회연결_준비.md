# 2번 구현 기록: 업무 목록·상세 조회 연결 준비

기록일: 2026-10-16

[담당 목록](README.md) · [전체 기록](../README.md) · [기존 19번 기록](../LOG/2026-10-16/19_업무목록_상세_조회연결_준비.md)

이 문서는 2번 담당의 현재 완료 범위를 정리한다. 기존 19번 기록은 보존하며, 이 문서 작성으로 코드나 기능을 추가하지 않는다.
기준 게시본은 alpha와 `0.0.2V`가 가리키는 [8f09183](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/commit/8f09183ef992606ec4c2b7e3da79ef07983ba019)이다.

## 요청과 착수 판단

사용자는 alpha 구조를 유지하며 업무 목록·상세 연결을 시작하되, 먼저 1번의 인증·공통 HTTP·오류 응답·DB 규약을 대조하도록 요청했다.
감사한 저장소와 로컬 2차 프로젝트에는 해당 실행 코드·연결 계약이 없어, 읽기 인터페이스와 명시적 테스트 대역까지 준비했다.
이는 외부 팀원의 별도 작업이 없다는 뜻이 아니다. 계획서의 API·DTO·테이블도 기존 계약이 아닌 제안이다.

## 완료한 2번 범위

| 항목 | 현재 반영 |
|---|---|
| 화면 구조 | 기존 `LoginForm → MainForm → TasksControl`, 표준 `.cs`·`.Designer.cs`·`.resx` 유지 |
| 읽기 경계 | `ITaskQueryService`, `TaskListQuery`·`TaskSummary`·`TaskDetail`, 화면용 상태와 실패 분류 |
| 기본 실행 | `UnconfiguredTaskQueryService`로 조회 연결 필요 표시. 업무 예시로 자동 대체하지 않음 |
| 테스트 대역 | `TaskQueryTestDouble`을 생성자에 명시적으로 주입한 경우만 사용. 출처 문구 상시 표시 |
| 목록·상세 | 목록 응답 표시와 선택 행의 ID를 통한 상세 조회 연결 |
| 조회 조건 | 관리자 내 업무/관리 업무와 전체·5개 상태 필터를 전달하고 대역에서 조건별 목록 표시 |
| 조회 상태 | 로딩·빈 목록·미연결·인증 만료·권한 없음·미존재·서버 오류 표시와 재시도 |
| 응답 순서 | 취소 토큰·요청 세대·선택 ID로 늦은 응답과 잘못된 상세 ID 차단, 종료 중 요청 취소 |
| 첨부·처리 창 | 첨부 조회는 미연결로 비움. 기존 처리 창도 선택한 조회 업무와 연결되지 않았음을 안내 |

새 조회·실패·선택 변경 시 이전 상세를 정리한다. 오류가 나도 고정 샘플로 조용히 대체하지 않는다.
`TaskDisplayStatus`는 화면용 논리값이며 서버 저장 코드가 아니다. Own/Managed 테스트 집합도 인증·권한 매핑이 아니다.
등록·수정·취소·수락·검토/연장 요청 저장은 아직 미연결이다. 결과물 제출·재제출·제출 차수/버전 표시는 3번 범위이며 이번 2번 완료 항목이 아니다.

## 실제 연결에서 남은 검증

| 필수 검증 | 현재 상태 |
|---|---|
| 인증 사용자 기준 직원 own 및 관리자 own/managed 목록 범위 검사 | 서버 미구현·미실행 |
| 범위 밖 업무 ID로 상세에 직접 접근하는 수평 접근 우회 거부 | 서버 미구현·미실행 |
| 인증 누락·만료와 범위 위조 거부 | 서버 미구현·미실행 |
| 실제 HTTP·DB 조회/저장·서버 중단·두 PC·웹 통합 | 미실행 |

테스트 대역에서 오류 화면을 확인한 것은 실제 서버 권한 검사나 인증 만료·연동 검증을 통과한 것이 아니다.
화면 역할·범위·필터와 본문의 사용자 ID를 권한 증거로 쓰지 않으며, 목록과 직접 상세 조회를 서버가 각각 검사해야 한다.

## 확정 규칙과 합의 필요

단일 업무 상태는 **진행전 / 진행중 / 제출완료 / 승인완료 / 반려완료**다. 배정·수락·정식 제출·판단의 기본 전환은 확정이다.
모든 정식 제출·재제출은 관리자 판단이 필수이며 승인완료만 최종 완료다. 관리자 본인 제출본은 상위 검토자가 판단한다. 자동 제출은 제외한다.

| 연결 담당 | 남은 질문 |
|---|---|
| 1번 | 서버 실행법, 사용자 식별·인증 컨텍스트, 공통 HTTP·응답/오류, GET 필드·페이지·날짜와 관리 범위 |
| 1번·3번 | 상태 저장/응답 코드, 행동별 상태 연결, 상위 검토자 권한, 반려 후 재작업 복귀 시점 |
| 3번 | 별도 검토 요청 의미, 자동 검토 요청 도입·조건·중복, 연장 신청/반영 조건, 마감 후 직접 제출 조건 |

세부 근거는 [게시본 조회 경계 문서](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/blob/8f09183ef992606ec4c2b7e3da79ef07983ba019/RemoteWork.WinForms/Features/Tasks/Queries/README.md)와 [검증 범위](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/blob/8f09183ef992606ec4c2b7e3da79ef07983ba019/Tests/TaskQueries.Tests/README.md)를 따른다.
게시·문서 이력은 [17번](../LOG/2026-10-16/17_알파_0.0.2V_동기화.md)과 [18번](../LOG/2026-10-16/18_합의문서_최신화와_Word_정리.md)에 구분하며, 이번 기록은 실제 API·인증·HTTP·DB 구현 완료를 뜻하지 않는다.
