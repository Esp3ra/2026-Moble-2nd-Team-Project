## 확정된 원칙과 이미 수용된 표현

| 화면 | 코드 | 확정된 의미 |
|---|---|---|
| 진행전 | not_started | 배정 후 담당자가 수락하기 전 |
| 진행중 | in_progress | 직원 또는 관리자 본인이 수락해 업무 수행 중 |
| 제출완료 | submitted | 정식 제출·재제출 후 권한 있는 검토자의 판단 대기 |
| 승인완료 | approved | 검토자가 승인했고 업무 최종 완료 |
| 반려완료 | returned | 반려 판단 후 수정·재제출 필요. 최종 완료가 아님 |

5개 의미와 기본 행동 전환은 사용자 확정, 소문자 코드·날짜 표현은 1번 공통 지원 수용 기준입니다. **초기값을 어느 저장 단계에서 넣는지·행동별 갱신 책임·트랜잭션 연결**은 아래 답변이 필요합니다.

- 직원·관리자의 모든 정식 제출·재제출은 승인 또는 반려를 거칩니다. 별도 검토 요청을 하지 않았다는 이유로 제출본이 검토에서 누락되면 안 됩니다.
- 관리자 본인의 제출본은 상위 검토자가 판단하고 자기 승인·반려는 서버에서 거절합니다. 상위 검토자 관계는 아직 합의 필요입니다.
- 관리 업무 조회는 업무별 지정 관리자만입니다. `task_managers`는 조회 관계이며 검토자 계층·승인권한이 아닙니다.
- 시작/현재 마감은 NULL 없는 DATE / YYYY-MM-DD / DateOnly이며 기록 시각은 UTC입니다. DATE를 임의로 UTC 자정으로 변환하지 않습니다.
- **자동 결과 제출은 제외**합니다. 기한 경과만으로 제출본·제출 시각·차수·submitted 상태를 만들지 않습니다. 자동 검토 요청은 도입 여부부터 합의 필요입니다.
- 제출 차수 표시 ‘1차·2차…’는 3번 범위입니다. 배정 revision과 제출 차수는 별개이며 서로 같은 번호로 간주하지 않습니다.

## 받을 규약 — 기존 M3와 연결

## 답변에 포함할 허용 조건 표

특히 W3-01/03/06은 각 행동의 소유 담당과 상태/주체를 함께 적어 주세요. 미정 셀은 **합의 필요**로 남기면 됩니다. 이 빈 양식은 허용 정책을 미리 확정한 표가 아닙니다.

| 행동 | 실행 주체·관계 | 허용 상태 | 추가 조건·마감 영향 | 성공 저장/상태 | 실패 HTTP/code | 구현 담당 |
|---|---|---|---|---|---|---|
| 최초 배정/등록 | 합의 필요 | 합의 필요 | 합의 필요 | 합의 필요 | 합의 필요 | 2번 |
| 본인 수락 | 현재 배정 당사자 원칙 | 합의 필요 | 합의 필요 | 진행중 기본 전환 | 합의 필요 | 2번 |
| 기본정보 수정/재배정/취소 | 합의 필요 | 합의 필요 | 제출/판단 대상 보존 규약 필요 | 합의 필요 | 합의 필요 | 2번, 3번 경계 확인 |

## 회신 양식과 구현 순서

```text
항목 ID: W3-__ (기존 M3-__)

결정 또는 제안:
행동별 허용 주체·상태·조건:
API·DTO·테이블/FK·잠금/버전·감사 영향:
```

회신 후 **W3-01~04와 1번 쓰기 규약 대조 → 등록/배정 → 본인 수락 → W3-06에 따른 마감 관리 → 3번 구현이 제공한 제출/검토 접점 통합** 순서로 진행합니다. 상위 검토자 열람은 W3-05 확인 후 최소 범위로 연결하고, 자동 검토 요청은 W3-07 도입 합의가 있을 때만 별도로 진행합니다.
