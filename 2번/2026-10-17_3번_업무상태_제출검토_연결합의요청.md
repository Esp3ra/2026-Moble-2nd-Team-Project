# 3번 담당 전달 — 업무 상태·제출·검토 연결 합의 요청

작성일: 2026-10-17 · 전달: 2번 → 3번 · 상태: **연결 규약 합의 필요**

2번 업무 목록·상세를 1번 공통 인증·HTTP·DB에 맞춰 읽기 연결했습니다. 이제 3번의 제출·재제출·승인·반려 결과가 같은 업무 상태와 일치하도록 연결 규약을 확인하고 싶습니다. 아래 항목에 대해 현재 설계·구현 자료 또는 결정안을 회신해 주세요. **3번의 코드·테이블·API를 2번이 대신 구현하거나, 이 문서를 게시한 것만으로 규약을 확정하지 않습니다.**

조회 코드 기준은 [alpha 07e444d](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/commit/07e444dfa33a35ffbdce12d0120a77c05b027703)입니다. 공통 DB·migration·사용자 권한 기반에 대한 요청은 [1번 전달 문서](2026-10-17_1번_업무조회_API_DB_합의요청.md)로 나눴습니다. 양쪽에 영향을 주는 항목은 1번·2번·3번의 확인을 함께 기록합니다.

## 1. 사용자 확정 기준 — 다시 선택할 항목이 아님

| 업무 상태 | 확정 의미·기본 전환 |
|---|---|
| 진행전 | 업무 배정 후 담당자가 수락하기 전 |
| 진행중 | 직원 또는 관리자 담당자가 업무를 수락해 수행 중 |
| 제출완료 | 담당자가 결과를 정식 제출·재제출해 권한 있는 검토자의 판단을 기다림 |
| 승인완료 | 검토자가 승인했으며 업무가 최종 완료됨 |
| 반려완료 | 검토자가 반려했고 수정·재제출이 필요함. 최종 완료가 아님 |

- **배정 → 진행전, 수락 → 진행중, 정식 제출·재제출 → 제출완료, 승인·반려 → 승인완료·반려완료**의 기본 전환은 확정됐습니다. 반려 후 진행중으로 돌아오는 구체적인 계기와 저장 연결은 합의 필요입니다.
- 직원·관리자 모두 본인 업무를 수락·제출할 수 있습니다. **모든 정식 제출·재제출은 반드시 권한 있는 검토자의 승인 또는 반려를 거칩니다.** 별도 검토 요청 버튼을 누르지 않았다는 이유로 제출본을 검토 대상에서 누락하면 안 됩니다.
- 관리자의 본인 제출본은 **상위 검토자**가 판단하며 **자기 승인·자기 반려는 허용하지 않습니다.** 상위 검토자 계정·권한 매핑은 합의 필요입니다.
- **승인완료일 때만 최종 완료**입니다. 제출 성공·검토 요청 접수·관리자의 요청 읽음·반려 처리를 최종 완료로 보지 않습니다.
- **마감기한 경과에 따른 자동 결과 제출은 제외**합니다. 마감 경과만으로 제출본·제출 시각·제출 차수·제출완료 상태를 생성하지 않습니다.
- 사용자가 확정한 관리 업무 조회 범위는 **업무별 지정 관리자만**입니다. 이 조회 관계는 결과물의 검토·승인·반려 권한과 별개입니다.

## 2. 현재 2번이 제공하는 조회 개발 초안

현재는 목록·상세 GET만 구현했습니다. [조회 개발 계약](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/blob/07e444dfa33a35ffbdce12d0120a77c05b027703/docs/TASK_QUERIES.md)과 [읽기 모델](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/blob/07e444dfa33a35ffbdce12d0120a77c05b027703/RemoteWork.Server/remotework/features/tasks/models.py)을 먼저 확인해 주세요.

| 항목 | 현재 개발 동작·합의 경계 |
|---|---|
| 목록 | `GET /api/v1/tasks?scope=own` 또는 `scope=managed`, `status` 생략은 전체. 해당 범위·상태의 전체 목록을 반환하며 페이지·검색은 미지원 |
| 상세 | `GET /api/v1/tasks/{task_id}`. 요약 필드에 `description` 추가 |
| 식별자 | DB 업무 ID는 `BIGINT`, wire `task_id`는 문자열. 사용자 식별은 공통 정수 `users.id` |
| 상태 코드 초안 | `not_started` / `in_progress` / `submitted` / `approved` / `returned`. 5개 의미는 확정됐지만 **저장 코드·최초 저장 기본값·변경 연결은 공동 확인 전** |
| 업무·배정 | `tasks`에 단일 `task_status`, `current_assignment_revision`, `row_version`. `task_assignments`는 `(task_id, revision)`으로 현재 배정을 찾는 개발안 |
| 날짜 | `start_date`, `due_date`는 NULL 없는 DB DATE / `YYYY-MM-DD` / C# DateOnly 개발안. 날짜를 UTC 기록 시각과 구분 |
| 권한 | 본인 목록은 현재 본인 배정, 관리 목록은 현재 admin이면서 해당 `task_managers` 지정자인 업무. 상세도 서버에서 별도 검사 |
| 미제공 | 수락·상태 변경·제출·재제출·승인·반려·연장 저장, 결과물·파일·차수·이력 API 연결. **현재 GET 응답에 배정 차수·row_version은 노출하지 않음** |

`task_managers`는 **업무 조회 관계**입니다. 등록자·같은 부서·협업 참여자·상위 검토자를 지정 관리자나 승인권자로 자동 해석하지 않습니다. **상위 검토자로 지정됐더라도 현재 담당자나 지정 관리자가 아니면 현재 `GET /tasks/{task_id}`는 403입니다.** 검토자에게 업무 기본정보를 어떻게 제공할지 아직 구현하지 않았으며, 현재 본인/지정 관리자 조회와 별도로 범위·경로·서버 권한 검사를 합의해야 합니다.

위 API·DB는 개발 초안이며, 공유 DB에 적용하지 않았습니다. `REMOTEWORK_ENABLE_TASK_QUERY_DRAFT=1` 명시적 활성화와 삭제 가능한 개발·테스트 DB에서만 검증했습니다. API 활성화·init-db를 공유 DB migration의 대체 수단으로 쓰지 않습니다.

## 4. 회신 양식

아래를 M3-01~M3-08별로 복사해 답해 주시면 됩니다. 이미 구현한 계약은 자료를 연결하고, 결정되지 않은 것은 **합의 필요**와 선택지·담당자를 적어 주세요.

```text
항목 ID: M3-__
현재 상태: 기존 계약 있음 / 제안 / 합의 필요 / 공동 확인 완료
결정 또는 제안 내용:

API·DTO·DB 및 권한 영향:
작성/확인 담당자와 확인 날짜:
추가로 확인할 담당자·질문:
함께 실행할 통합 검증:
```

‘공동 확인 완료’는 실제 확인 담당자·날짜·근거를 남긴 항목에만 사용합니다. 문서 게시나 격리 테스트 성공만으로 1번·3번 확인이 끝났다고 표시하지 않습니다. 스키마 적용·migration은 1번과 별도 확인한 뒤 진행합니다.

## 5. 확인 이후 연결·검증 범위

- 2번은 합의된 결과를 업무 조회 DTO·상태 표시·행동별 호출 경계에 반영합니다. 3번은 제출·파일·차수·검토·판단·이력 계약과 해당 구현을 담당합니다. 공통 사용자·인증·오류·DB/migration은 1번 규약을 재사용합니다.
- 통합 시 직원과 관리자 본인의 수락·제출·재제출, 필수 검토 대상 연결, 상위 검토자 판단, 자기 판단 거부를 확인합니다. 승인 전 최종 완료가 되지 않는지도 확인합니다.
- 제출/판단 중복·경합·롤백·응답 유실, 옛 배정/옛 버전 요청, 반려 후 합의된 복귀, 연장/마감 후 직접 제출 조건, 타인 결과·첨부·이력 접근 거부를 담당별 구현 후 함께 확인합니다. 상위 검토자만인 계정의 기본정보 열람은 합의한 방식·필드 안에서 허용되는지, 그 밖의 업무 조회나 자기 판단으로 권한이 확대되지 않는지도 확인합니다.
- 자동 검토 요청을 도입하기로 합의한 경우에만 그 중복·재실행을 검증합니다. **자동 결과 제출은 검증을 위한 기능으로도 추가하지 않습니다.**

지난 조회 개발에서는 격리 MySQL의 명시적 fixture를 사용한 실제 HTTP·목록·상세·권한 검증을 했습니다. 이번 문서 작성에서 해당 테스트를 재실행한 것은 아니며, **3번 제출·검토·파일·차수·이력 및 상태 변경 통합은 미실행**입니다. 공유 DB·운영 데이터·두 PC·웹 업무 연동도 완료로 표시하지 않습니다. 세부 근거는 [실제 조회 개발 기록](2026-10-17_업무목록_상세_실제조회_개발초안.md)을 따릅니다.
