# 2번 — 합의 회신 전 진행 가능 범위 점검

작성일: 2026-10-17 · 현재 코드 [alpha 329d4a3](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/commit/329d4a32ff316ed2ae208a40e5b1ba0f743d958c)

1번·3번의 답변 전에도 진행할 수 있는 범위를 최신 조회 계약·전달문·실제 소스와 대조했다. 기존 화면·조회 인터페이스·5개 상태 의미를 유지하면서 **조회 사용성과 취소 처리·이미 요청한 필터의 응답 검증**을 개선했다. API 경로·DTO·DB·권한·상태 전환 계약을 새로 확정하지 않았다.

## 지금 진행할 수 있는 부분과 이번 결과

| 작업 | 독립 진행이 가능한 이유 | 이번 결과 |
|---|---|---|
| 같은 조회 조건의 선택 유지 | 이미 받은 목록의 UI 선택 문제이며 서버 계약을 바꾸지 않음 | 선택 ID가 새 목록에 있으면 유지, 없으면 첫 행, 빈 목록은 초기화 |
| 실패한 상세만 재시도 | 기존 GetTaskAsync를 같은 업무 ID로 명시 재호출 | 목록 호출 없이 해당 상세만 재시도, 성공 후 전체 재조회로 복귀 |
| F5 목록 새로고침 | 기존 GetTasksAsync 재호출이며 새 저장 기능이 아님 | 자식 컨트롤에서도 전체 재조회. 삭제된 상세404 뒤 목록 복구 가능 |
| 접속 취소와 서버 오류 구분 | 1번 ApiClient가 이미 전달하는 OperationCanceledException 활용 | 이전 목록·상세 제거·취소 안내·명시 재시도. 늦은 취소는 최신 결과를 바꾸지 않음 |
| 상태 필터 응답 검증 | 이미 요청한 상태와 응답의 일치 검사이며 상태 코드를 새로 정하지 않음 | 불일치가 한 건이라도 있으면 전체 응답 거절. 빈 결과·전체 조회·상세의 이후 상태 변경은 정상 허용 |
| 회귀·문서 정리 | 기존 구현의 정확성 확인이며 다른 담당 기능을 구현하지 않음 | 원본 결함 재현·현재 회귀 통과, README·조회 계약 설명 최신화 |

## 회신 후 진행할 부분

| 항목 | 필요한 합의·담당 |
|---|---|
| 업무 등록·수락·수정·재배정·취소·연장 등의 저장 | 1번 FK/transaction/migration, 3번 제출 이후 변경 조건과 상태 연결 |
| API/DTO·상태 저장 코드·날짜 의미·페이지/검색의 공유 계약 확정 | 1번·2번, 상태/마감 연결은 3번 |
| 상세403/404 정책 변경·협업/상위 검토자 조회 권한 확대 | 1번·2번·3번·팀장, 협업은 4번 |
| 제출·재제출·승인·반려·결과물·파일·차수·이력 | 3번 계약·구현, 2번은 합의한 호출 경계만 연결 |
| 반려 후 진행중 복귀·자동 검토 요청·마감 후 직접 제출 | 2번·3번 등 관련 담당의 행동/조건 결정 |
| 공유 DB migration·업무 API 정식 활성화·운영 데이터 적용 | 1번과 schema version·백업/복구·공유 환경 확인 |

관리 범위인 **업무별 지정 관리자만**, 5개 상태 의미·필수 승인/반려·자기 판단 금지·자동 결과 제출 제외는 기존 확정 기준이다. 위 대기 항목 때문에 이를 다시 미정으로 돌리지 않는다. 자동 결과 제출은 추가하지 않는다.

## 이번 검증과 미실행 범위

- 업무 UI: 9시나리오·82 assertion PASS. 기존6/47 포함, 명시적 조회 대역+실제 WinForms 메시지 루프.
- HTTP/화면: 6시나리오·103 assertion PASS. 기존4/77 포함, 실제 공통 ApiClient+명시적 HTTP 대역+실제 TasksControl.
- 기존 공통 ApiClient: 18시나리오·88 assertion PASS.
- 개발 checkout 및 실제 로컬 솔루션 Release: 각각 경고0·오류0.
- 원본07e444d의 격리 소스에서는 신규 선택/상세재시도/외부취소 회귀가 각각 실패함을 확인했다. 필터 불일치·공통 접속 취소→화면 회귀도 원본 결함을 검출했다.
- 대표 상세 실패·취소·850×620 화면을 확인했다. 기존 스크롤과 Designer 구조를 유지했다.

이번에는 서버·DB 소스를 변경하지 않았고 실제 서버/MySQL·공유 DB·두 PC·웹·3번 제출/검토 통합 테스트를 재실행하지 않았다. 앞선 MySQL37통과·실제HTTP 직원19/관리자21 수치는 [이전 개발 회차](2026-10-17_업무목록_상세_실제조회_개발초안.md)의 기록으로 보존하며 이번 수치에 합산하지 않는다.

## 변경·게시 범위

alpha의 변경11개는 TasksControl·HTTP 조회 서비스·조회 경계 설명 주석2개·UI/HTTP 테스트2개·README/조회 문서5개다. 서버/DB·공통 인증·Designer·3·4·5번 기능은 그대로다. 로컬에는 변경11개만 동기화했고 추적 소스152개 일치·DOCX7개 해시 보존·로컬 Release0/0을 확인했다.

코드는 alpha, 이번 문서는 LOG/2번에 게시한다. 1번·3번 전달문과 기존 기록은 보존하고, 답변이 오지 않은 항목은 합의 필요로 유지한다. DOCX·main·PR·0.0.1V·0.0.2V는 변경하지 않는다.
