## 현재 구현 범위

현재 alpha 기준은 [07e444d](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/commit/07e444dfa33a35ffbdce12d0120a77c05b027703)이며 0.0.2V는 이전 8f09183으로 보존합니다. 공통 기반을 재사용한 **목록·상세 GET·실제 HTTP·격리 DB·기존 WinForms 읽기 연결 개발 초안**을 구현·검증했습니다. 관리 범위는 사용자 확인에 따라 업무별 지정 관리자만입니다. API/상태/날짜/스키마는 관련 담당의 최종 합의가 필요하므로 업무 API는 명시적 개발 활성화일 때만 등록합니다. 공유 DB·운영 업무 데이터·두 PC·웹 연결 완료로 표시하지 않습니다.

| 항목 | 현재 상태 |
|---|---|
| 기존 업무 화면 구조·Designer 유지 | 반영 완료 |
| 목록·상세 조회 인터페이스와 화면 모델 | 준비 완료 |
| 기본 서버 비활성화·미등록 경로의 연결 필요 안내 | 반영 완료. 일반 초기화의 미확정 업무 테이블 자동 생성 방지 |
| 명시적 테스트 대역과 출처 표시 | 반영 완료 |
| 행 선택 상세·전체 및 5개 상태 필터 | 조회 경계에 연결, 테스트 대역으로 검증 |
| 로딩·빈 목록·오류 구분·재조회 | 테스트 대역으로 검증 |
| 늦은 응답 차단·잘못된 상세 ID·종료 중 요청 | 테스트 대역으로 검증 |
| 실제 인증·HTTP·DB·서버 조회 권한 | 공통 규약 재사용, 본인 현재 배정·지정 관리자·직접 상세 권한을 격리 MySQL/실제 HTTP·화면에서 검증. 공유 DB 적용·계약 최종 합의는 필요 |
| 등록·수정·수락·마감 연장 등의 저장 | 아직 구현하지 않음 |

## 담당 경계와 합의

- 1번의 인증 사용자·공통 HTTP·오류·DB 연결 규약은 2번이 대신 구현하지 않습니다. 실제 서버는 본인 배정·허용된 관리 범위와 상세 직접 접근 권한을 검사해야 합니다.
- 3번의 제출·재제출·제출 차수 표시·파일·승인·반려·이력과 4·5번의 기능은 해당 담당과 분리합니다. 화면 뼈대가 있다는 이유로 연결 완료로 기록하지 않습니다.
- 5개 업무 상태와 모든 정식 제출의 필수 검토는 확정 기준입니다. 상태 저장 코드·상위 검토자 매핑·반려 후 복귀 시점·마감 세부 조건은 합의 필요입니다.
- 자동 결과 제출은 제외합니다. 자동 검토 요청의 도입 여부·조건은 합의 질문으로 유지합니다.
