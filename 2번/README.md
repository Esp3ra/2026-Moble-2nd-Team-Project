## 현재 구현 범위

현재 소스 기준은 alpha·0.0.2V의 [8f09183](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/commit/8f09183ef992606ec4c2b7e3da79ef07983ba019)입니다. 1번의 실제 공통 서버·인증·HTTP·오류·DB 계약은 확인되지 않아, 이번 완료 범위는 **읽기 인터페이스와 명시적 테스트 대역을 통한 화면 연결 준비**입니다. 실제 업무 데이터 연동 완료로 표시하지 않습니다.

| 항목 | 현재 상태 |
|---|---|
| 기존 업무 화면 구조·Designer 유지 | 반영 완료 |
| 목록·상세 조회 인터페이스와 화면 모델 | 준비 완료 |
| 기본 실행의 조회 미연결 안내 | 반영 완료 |
| 명시적 테스트 대역과 출처 표시 | 반영 완료 |
| 행 선택 상세·전체 및 5개 상태 필터 | 조회 경계에 연결, 테스트 대역으로 검증 |
| 로딩·빈 목록·오류 구분·재조회 | 테스트 대역으로 검증 |
| 늦은 응답 차단·잘못된 상세 ID·종료 중 요청 | 테스트 대역으로 검증 |
| 실제 인증·HTTP·DB·서버 조회 권한 | 계약 확인과 실제 연동·검증 필요 |
| 등록·수정·수락·마감 연장 등의 저장 | 아직 구현하지 않음 |

## 담당 경계와 합의

- 1번의 인증 사용자·공통 HTTP·오류·DB 연결 규약은 2번이 대신 구현하지 않습니다. 실제 서버는 본인 배정·허용된 관리 범위와 상세 직접 접근 권한을 검사해야 합니다.
- 3번의 제출·재제출·제출 차수 표시·파일·승인·반려·이력과 4·5번의 기능은 해당 담당과 분리합니다. 화면 뼈대가 있다는 이유로 연결 완료로 기록하지 않습니다.
- 5개 업무 상태와 모든 정식 제출의 필수 검토는 확정 기준입니다. 상태 저장 코드·상위 검토자 매핑·반려 후 복귀 시점·마감 세부 조건은 합의 필요입니다.
- 자동 결과 제출은 제외합니다. 자동 검토 요청의 도입 여부·조건은 합의 질문으로 유지합니다.

## 기록 작성 기준

새 구현 기록은 `2번/YYYY-MM-DD_작업내용.md`로 작성합니다. 문서에는 변경 파일, 구현 범위, 실제 실행한 검증, 실행하지 못한 검증과 합의가 필요한 항목을 구분합니다. 푸시할 때 이 목록과 LOG 루트 README도 최신화합니다.

기존 공통 날짜별 기록은 원래 경로에 보존합니다. [기존 19번 기록](../LOG/2026-10-16/19_업무목록_상세_조회연결_준비.md)은 당시 공통 작업 이력이며, 이후 2번 기능 구현 기록의 기준 위치는 이 폴더입니다.
