새 실제 HTTP 검증은 임시 Flask 서버의 TCP 연결을 통과해 SQLite ORM 데이터를 읽고 실제 WinForms 메시지 루프에 표시합니다. 화면은 자동 검증용으로 화면 밖에서 생성합니다. 36/52와 runner300은 각각의 검증 범주로 표기하며, 그중 권한 회수11은300에 포함합니다. 정렬 fixture 보강 전후 반복 통과 수치를 합산하지 않습니다. 처음의 기본 HTTP 실행 후 새 C# 소스를 명시 빌드하고 다시 통과한 것을 확인했습니다.

직접 HTTP는 정확한 내/관리 목록·5필터·빈 목록·미인증401·타인/비지정403·업무 미존재404·로그아웃 토큰 거절을 확인했습니다. C#은 별도 HTTP 호출로 자신의 서버 접속을 폐기한 뒤 다음 조회의401·인증 만료 표시·목록 제거·공통 사용자 초기화를 확인합니다. 시간 경과로 세션이 만료되는 경우와는 구분합니다.

지정 관리자 관계 제거와 담당자 재배정은 **삭제 가능한 fixture 내부에서만** 수행했습니다. 관계 회수 후 managed목록 제외·직접403, 재배정 후 옛 담당자 목록 제외·직접403·새 담당자의 목록/상세 허용을 확인했습니다. 이 결과는 제품의 재배정 API나 상태 전환 구현을 뜻하지 않습니다.

C# 실행 전후에는 업무·배정·지정 관리자3개 테이블의 해시를 비교했습니다. 로그인 후 GET 묶음 전후에는 같은 SQLite의 전체 행을 메모리에서 해시해 업무·공통 감사 이력 등 DB 내용이 바뀌지 않는지 확인했습니다. 원시 행·자격 증명·SQL dump는 게시하지 않습니다. 정상 실행과 의도적인 실패 모두 전용 자식 서버 종료·임시 경로 정리를 확인했습니다.

## 실행 방법

Windows·.NET8 SDK/런타임·Python3.11 이상과 서버 의존성을 준비한 뒤 프로젝트 루트에서 실행합니다.

```powershell
dotnet build .\Tests\TaskQueries.Http.Tests\TaskQueries.Http.Tests.csproj -c Release
.\RemoteWork.Server\.venv\Scripts\python.exe .\Tests\TaskQueries.Http.Tests\run_http_check.py
```

현재 Python 환경에 `RemoteWork.Server/requirements.txt` 패키지가 필요합니다. 실제 테스트에서는 격리된 기존 검증용 Python 환경으로 실행했습니다. 일반 서버 시작·공유 DB 설정·실제 계정 전달은 필요하지 않습니다. 상세는 [코드 브랜치 안내](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/blob/8a652adaba4a8471b2fff581f1265bf27c8ff1d3/Tests/TaskQueries.Http.Tests/README.md)를 따릅니다.
