M1-06에서 **표현 형식** 수용과 **업무 전환/마감 의미** 합의는 구분한다. M1-07의 타입 호환과 M1-08의 번호 예약은 실제 DDL 승인과 구분한다. task_managers는 조회 관리 관계이며 제출 검토자·조직 계층을 대신하지 않는다.

## 이어서 진행할 순서

1. **이번 진행:** 수신/추적 문서 최신화, 기존 모델과 일치하는002 검토용 DDL 및 삭제 가능한 별도 MySQL 검증·복구안 준비.
2. **3번 회신 후:** M3-01~08을 대조해 상태 전환 책임, 제출본의 배정 차수, 검토자 열람, 반려 후 복귀·마감 의미·감사/버전 갱신을 공동 확정. 기존 [3번 전달문](2026-10-17_3번_업무상태_제출검토_연결합의요청.md) 사용.
3. **DDL/공통 지원 검토:** 2번이 합의 내용을 반영한 DDL·쓰기 정합성안을 만들고 1번이 FK/기대 버전 지원·적용 순서를 검토. 현재 버전1을 임의 증가시키지 않음.
4. **2번 저장 구현:** 확정된 계약 순서대로 등록/배정/본인 수락·마감 관리 구현. 3번의 제출/재제출/승인/반려·파일·차수·이력은 해당 담당 코드와 연결하며 대신 구현하지 않음.
5. **공유 검증:** 공식 서버·계정·백업/복구·적용 일정 확인 후 실제 업무 데이터·권한·두 PC를 검증. 격리 fixture 통과와 구분.

모든 정식 제출은 승인 또는 반려를 거치고 관리자 본인 제출은 상위 검토자가 판단한다. 자동 결과 제출은 제외한다. 자동 검토 요청·미확정 상태 복귀·마감 후 직접 제출은 합의 필요로 유지한다.

## 검증과 미실행

현재 소스/회신 대조와 변경 범위·Markdown 검사를 수행했다. 예약 DDL의 실제 실행·실패/복구와 서버 회귀 결과는 별도 DDL 기록에 실행 수치/환경과 함께 남긴다. 문서·주석 변경만으로 WinForms 수동 검토나 두 PC 검증을 재실행했다고 표시하지 않는다.

공통 서버 가용성은 1번 회신의 관측 시점을 유지한다. 이전 health200 이후 문서 업로드 후 연결 거부가 기록되어 있으므로 현재 공유 서버 접속 가능으로 안내하지 않는다. 이번에는 해당 서버/DB를 시작·중지·초기화하지 않는다. 실제 설정·비밀번호·토큰·덤프와 로컬 DOCX는 게시하지 않는다.
