연장 희망일을 현재 마감일보다 늦게 제한하거나 특정 상태만 허용하는 정책은 추가하지 않았습니다. 시작일/마감일의 업무 시간대·종료 시각·기한 후 수락/제출 조건도 이번 로컬 검사로 결정하지 않습니다.

## 선택 문맥·날짜·기존 화면 보존

TasksControl의 수정·수락·마감 연장 버튼은 **현재 행의 상세 조회가 성공하고 ID가 일치할 때만** 사용할 수 있습니다. 선택/범위/상태 변경·목록 새 조회·로딩·상세 실패·인증 실패·취소·빈 목록·종료에서는 이전 상세 캐시를 무효화하고 대상 버튼을 차단합니다. 늦은 상세 응답이 새 선택의 처리 대상이 되지 않도록 기존 요청 세대/ID 검사를 유지했습니다.

폼에는 불변 TaskDetail을 전달해 표시하며 원래 업무 객체·목록·상태를 수정하지 않습니다. 현재 조회 화면 DTO에는 담당자 ID·배정 차수·row_version이 없습니다. 이름으로 사용자 ID를 추정하지 않고 담당자 선택은 비활성으로 표시합니다. 공통 사용자 관리 GET을 배정 가능 사용자 계약으로 간주하지 않습니다.

DateOnly는 WinForms 날짜 입력기보다 범위가 넓습니다. 수정 대상의 원본 날짜가 입력기 지원 범위 밖이면 해당 원본을 정확한 문자열로 표시하고 입력 확인을 차단합니다. 경계 날짜로 자동 보정하지 않으며 날짜를 UTC 자정으로 변환하지 않습니다. 연장의 현재 마감일은 읽기 전용 원본 문자열로 보존합니다.

기존 TasksControl/UserControl·표준 `.cs/.Designer.cs/.resx` 구조를 유지했습니다. 등록/수정 폼 기본 높이를700으로 늘려 하단 안내를 확보했고, 오류는 ErrorProvider와 하단 문구로 안내합니다. 3번 ReviewRequestForm·TaskRequestsForm·결과물·첨부·차수·검토/판단 기능은 이번 수정에서 변경하지 않았습니다. 1번 공통 인증/HTTP/DB·서버 조회·DDL도 변경하지 않았습니다.
