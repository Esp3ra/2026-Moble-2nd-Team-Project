# W1 후보·쓰기 준비 화면 연결

2026-10-17 · 2번 담당 및 팀장: 사용자 본인. 팀장 별도 인물이 있다는 이전 표현은 이 확인을 기준으로 정정합니다. 3번 W3와 미정 정책은 관련 담당과 맞추고 최종 팀장 확인은 사용자에게 받습니다.

## 구현 순서와 결과

1. 별도 후보/페이지/쓰기 문맥/키·결과 DTO와 ITaskPreparationService를 추가했습니다. 기존 업무 GET/ITaskQueryService·CheckedInput을 유지합니다.
2. 공통 CaptureSession에 묶인 HTTP 서비스를 선택적으로 주입해 MainForm·공통 파일·3번 폼을 직접 변경하지 않았습니다.
3. 업무 화면의 ‘업무 연결 정보’, 등록/수정 창의 ‘담당자 · 업무 관리자 선택’을 연결했습니다. 사용자 ID로 단일 담당자·복수 업무 관리자를 보관하고 검색/페이지 중 선택을 유지합니다.
4. 로딩/실패/빈 목록·권한 회수·같은 사용자 재로그인·늦은 응답을 구분하고 이전 문맥/선택을 지웁니다. 키/결과 조회 경계와 충돌 분류는 구현했으나 화면에서 키를 자동 발급하거나 행동을 재전송하지 않습니다.
5. 실제 새 MySQL에서 업무/배정/관리자 행 전후 일치와 receipt0건을 확인했습니다. 선택값은 별도 PreparedSelection이며 서버 저장 요청/완료가 아닙니다.
