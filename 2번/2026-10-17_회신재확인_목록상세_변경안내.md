## 합의 없이 진행하는 읽기 화면 범위

목록 조회 뒤 상세를 조회하기 전 다른 사용자가 제목·담당자·상태·날짜를 바꿀 수 있습니다. 같은 업무 ID의 상세가 최신 정보인 경우 이를 오류로 거절하지 않습니다. 기존 화면은 최신 상세를 표시하지만 목록과 달라진 이유를 안내하지 않아 서로 다른 상태/날짜가 동시에 보일 수 있었습니다.

이번 변경은 기존 TaskSummary 값을 대조해 차이를 안내합니다. DB row_version·배정 revision 검증이나 쓰기 충돌 검사가 아니며, 별도 API·DTO·DB 정책을 요구하지 않습니다.

1. 목록에서 선택한 행과 성공한 상세의 업무 ID를 확인하는 기존 검사를 유지합니다.
2. 같은 ID의 제목·담당자 표시명·5개 상태·시작일·마감일이 달라졌으면 최신 상세를 표시하고 목록 새로고침이 필요함을 안내합니다.
3. 기존 목록 행·행 Tag·현재 범위/상태 필터는 자동 변경하지 않습니다. 선택한 상태와 최신 상세 상태가 달라도 상세 성공을 허용합니다. 목록을 자동 재조회하거나 서버 전체 목록/정렬 계약을 바꾸지 않습니다.
4. 안내에 제공하는 목록 새로고침은 기존 전체 조회 경로를 사용합니다. 같은 조건에서 선택 유지·진행 요청 취소·로딩/빈 목록/오류 처리는 기존 흐름을 재사용합니다. 새 필터 결과에 해당 업무가 없으면 이전 행을 억지로 남기지 않습니다.
