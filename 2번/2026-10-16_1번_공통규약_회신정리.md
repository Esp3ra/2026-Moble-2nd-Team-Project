# 1번 공통 규약 회신 정리

기록일: 2026-10-16 · 대상: 2번 업무 목록·상세 조회 연결

[2번 담당 기록](README.md) · [업무 조회 인터페이스·DTO 전달](2026-10-16_업무조회_인터페이스_DTO_전달.md)

이 문서는 **사용자가 직접 전달한 1번 담당의 회신**을 정리한다. 아래 구현·규약 정보는 1번이 공유한 내용이며, 이 PC에서 실행·통합 검증한 결과가 아니다.
앞선 감사에서 공통 코드를 찾지 못한 사실과 이번 회신을 구분한다. 공통 구현이 다른 PC나 별도 위치에 있다는 회신을 받았지만 이 PC의 연결 작업은 아직 시작하지 않았다.

## 1. 전달받은 공통 구현과 규약

| 항목 | 1번이 공유한 내용 |
|---|---|
| 개발 기본 주소 | `http://127.0.0.1:5000/api/v1` |
| 실행 파일 | `Start-MySQL.cmd`를 사용하는 실행 안내 |
| 로그인 입력 | `POST /api/v1/auth/login`에 JSON의 `login_id`, `password` 전달 |
| 로그인 결과·전달 | `data.access_token`을 받아 이후 요청에 `Authorization: Bearer {토큰}` 헤더 전달 |
| 현재 사용자 | `GET /api/v1/auth/me`로 로그인 사용자 확인 |
| 인증 수명·폐기 | 기본 유효 시간 8시간. 만료·로그아웃·비밀번호 변경·계정 비활성화에 따른 접속 폐기 구현 |
| 사용자 식별자 | `data.user.id`: DB 정수 사용자 ID, `data.user.login_id`: 로그인 아이디 |
| 역할 값 | `data.user.role`: `admin` 또는 `employee` |
| 서버 권한 기준 | 요청으로 받은 사용자 ID·역할을 신뢰하지 않고 인증된 사용자 정보로 판단 |
| 공통 응답 | `ok`, 성공의 `data` 또는 실패의 `error`와 `code`·`message`, `request_id` |
| 필드·시각 | `snake_case`, UTC ISO 8601 형식 |
| 인증·권한 오류 | 401 인증·만료, 403 권한 없음 |
| DB 오류 | 503 DB 연결·초기화 문제 |
| C# 통신 계층 | 공통 C# HTTP 클라이언트와 오류 처리가 준비됐다는 회신 |
| 서버 접근 도구 | 인증·접근 검사를 위한 도구가 있다는 회신. 업무 API 적용·검증과는 구분 |

성공 응답:

```json
{"ok":true,"data":{},"request_id":"요청번호"}
```

실패 응답:

```json
{"ok":false,"error":{"code":"오류코드","message":"안내문구"},"request_id":"요청번호"}
```

위 로그인·사용자 경로는 회신으로 전달받은 규약이다. 클라이언트의 실제 파일·공개 시그니처·세부 오류 코드는 공유 소스를 확인한 뒤 사용한다.
공유 문서의 업무 API 코드는 연결 예시이며 실제 등록된 업무 API가 아니라는 설명을 함께 받았다. 업무 API나 업무 테이블의 구현 완료 근거로 사용하지 않는다.
다른 PC에서는 서버 PC의 IP·외부 접속 허용·방화벽 설정이 필요하며, 두 PC 연결은 1번도 아직 검증하지 않았다고 전달했다.

| 문서 본문 | 위 `INTEGRATION.md`를 직접 열거나 내용을 대조하지 못함 |

`127.0.0.1`은 실행하는 PC 자신을 가리킨다. 전달받은 주소를 이 PC에서 1번의 서버로 연결할 주소라고 확정하지 않는다.
서버를 어느 PC에서 실행할지와 이 PC에서 사용할 접근 주소·공통 코드 위치를 먼저 확인해야 한다.
로컬 파일 부재를 외부 팀원 구현 부재로 해석하지 않으며, 회신만으로 로컬 실행 성공을 주장하지 않는다.

## 3. 아직 확정되지 않은 업무 조회 계약

| 항목 | 필요한 확인 |
|---|---|
| 실제 목록·상세 API | 메서드·경로·담당·구현 여부, 성공·빈 목록·실패 JSON 예시 |
| 필드 매핑 | 업무 ID, 제목, 담당자 표시명, 상세 내용, 현재 적용 마감일과 NULL 허용 여부 |
| 업무 상태 코드 | 5개 화면 상태와 실제 저장·응답 코드의 대응 |
| 필터·페이지 | Own/Managed 표현, 전체·상태 조건, 페이지 방식·크기·기본 정렬·페이지 메타 |
| 직원 노출 범위 | 본인 현재 배정 기준과 협업 참여 업무를 추가로 노출할지 여부 |
| 관리자 관리 범위 | 전체 부서인지 조직·부서 등으로 제한하는지와 그 권한 기준 |
| 오류 매핑 | 공통 오류를 현재 UI 실패 의미로 변환하는 방식, 상세 거부·미존재 정책 |
| 날짜 | 업무 시작일·마감일의 날짜/시각 구분과 형식·NULL·시간대 |

공통 인증·접근 도구가 있다는 것만으로 업무 목록·상세의 권한 검사가 완료된 것은 아니다.
인증 사용자 기준 own/managed 목록 제한과 타인·관리 범위 밖 ID의 직접 상세 접근 거부를 실제 업무 API에서 검증해야 한다.
현재 `ITaskQueryService`는 내부 읽기 경계이며 기본 실행은 `UnconfiguredTaskQueryService`, 테스트 대역은 명시적 주입만 사용한다.
이 회신 정리만으로 HTTP 어댑터·인증·DB·서버 권한 검사를 구현하거나 테스트 대역을 실제 서버로 바꾸지 않았다.

## 4. 유지할 원칙과 공동 합의

- 업무 상태는 **진행전 / 진행중 / 제출완료 / 승인완료 / 반려완료** 5개이며 기본 행동별 전환은 확정이다.
- 직원·관리자의 모든 정식 제출·재제출은 관리자 판단이 필수이며 승인완료만 최종 완료다. 관리자 본인 제출본은 상위 검토자가 판단한다.
- **마감 경과에 따른 자동 제출은 제외**한다. 자동 검토 요청은 별도로 도입·조건 합의가 필요하다.
- 상태 저장/응답 매핑, 행동별 연결·트랜잭션, 상위 검토자 권한, 반려 후 진행중 복귀 시점은 1번·3번 공동 합의 사항이다.
- 별도 검토 요청 의미, 연장 신청/반영 조건, 마감 후 직접 제출 조건도 합의 후 연결한다.
- 제출·재제출·제출 차수/버전 표시·승인·반려는 3번 범위다. 이번 회신으로 해당 표시 작업을 2번이 재개하지 않는다.

## 5. 다음 연결 전 확인할 자료

1. 공통 소스와 `INTEGRATION.md`를 확인할 저장소·브랜치·기준 커밋 또는 전달 가능한 사본.
2. 실제 공통 클라이언트·인증 컨텍스트의 사용 예시와 이 PC의 실행·접속 주소, 설정 템플릿.
3. 구현된 업무 API가 있다면 실제 요청·응답과 담당 정보. 없다면 2번 API 구현 전 맞출 계약.
4. 본인·타인·관리 범위 밖 업무와 인증 만료를 확인할 테스트 계정·데이터의 준비·전달 방법.

실제 HTTP·인증·DB 조회/저장·서버 권한·서버 중단·두 PC·웹 통합은 여전히 미실행이다.
회신 근거는 사용자가 전달한 1번 답변이며, 로컬 근거는 위 경로·파일의 읽기 전용 존재 확인이다. 이번 반영은 LOG 문서에 한정하며 코드·DB·태그를 변경하지 않는다.
