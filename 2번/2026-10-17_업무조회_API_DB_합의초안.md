# 2번 업무 목록·상세 조회 — API·DB 합의 정리

작성일: 2026-10-17 · 상태: **공통 규약 확인·관리 범위 사용자 확정 / 조회 개발 초안 구현 / 공유 API·DB 합의 필요**

최초 조사 기준은 [alpha 9b8d00c](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/tree/9b8d00cebe3e8a2a5555e06bcc512a802cc8152b)이다. 당시 등록된 공통 API 규칙은 10개, 공통 테이블은 7개였으며 업무 API·업무 테이블은 없었다. [DOCX 계획](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/blob/5ee0998b81c6519b60fd380ac46c719d67a63d80/DOCX/2번_업무_상태_마감_구현계획.md)의 경로·테이블은 제안으로 확인했다. 개발 전에 초안을 작성하고 사용자에게 관리 범위와 기존 합의·데이터 유무를 확인했다.

이후 사용자 회신에 따라 관리 범위를 확정했고 [현재 조회 개발 계약](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/blob/07e444dfa33a35ffbdce12d0120a77c05b027703/docs/TASK_QUERIES.md)으로 구현·격리 검증했다. 코드 구현과 별개로 아래 API·상태 코드·DB/migration이 1번·3번과 모두 합의됐다고 표시하지 않는다. 공유 DB에는 적용하지 않았다.

## 확인한 공통 규약 — 재구현하지 않음

| 항목 | 실제 적용 규약 |
|---|---|
| API/응답 | `/api/v1`, UTF-8 JSON, snake_case, 성공 `ok/data/request_id`, 실패 `ok/error.code/error.message/request_id` |
| 인증·사용자 | 공통 login/me·Bearer·서버 `g.user`, 정수 `users.id`, `admin/employee`; 클라이언트 사용자 ID·역할은 권한 증거가 아님 |
| C# | `AppServices.Api` 공유, 서버 루트 설정, 상대 경로 호출. 토큰·세대·취소·401 만료 처리 재사용 |
| 오류 | 400 입력, 401 인증, 403 권한, 404 미존재, 503 DB. 통신/timeout StatusCode=0. 문자열로 오류 종류를 판정하지 않음 |
| DB | 공통 Base·get_db·transaction·동일 트랜잭션 감사 이력. 사용자 테이블·인증·HTTP·DB 연결을 별도로 만들지 않음 |
| 기록 시각 | utcnow와 UTC ISO 8601. 날짜를 UTC 자정으로 임의 변환하지 않음 |
| 스키마 | 공통 버전1 유지. init-db는 기존 열 migration이 아니며 공유 DB 변경은 1번과 조정 |

공통 grant는 read/manage를 구분하지 않고 `allow_admin=True`는 관리자 grant 검사를 생략한다. 따라서 일반 grant나 관리자 역할만으로 업무 전체 접근을 허용하지 않았다.

## 사용자에게 확인한 결정

2026-10-17 이 작업의 직접 회신:

- 관리 업무 조회 범위: **업무별 지정 관리자만**.
- 이미 합의한 업무 API/DB 및 기존 업무 데이터·테이블: **없음**.

이를 근거로 본인 현재 배정과 업무별 지정 관리자 관계를 구분했다. 업무 관리 관계를 3번의 상위 검토자·승인권자로 간주하지 않는다. 협업·같은 부서·업무 등록자 관계도 자동 접근 근거로 확정하지 않았다.

## 2번 조회 개발 API·DB 초안

| 구분 | 현재 개발 동작 | 추가 합의 |
|---|---|---|
| 목록 | `GET /api/v1/tasks?scope=own|managed`, `status` 생략=전체 | 경로·DTO 최종 확인 |
| 전체 목록 | data=`{items:[...]}`, `due_date ASC, task_id ASC`, 절단 없는 전체 반환 | 페이지·검색 도입 시 공통 PageResult와 UI/경계 함께 결정 |
| 상세 | `GET /api/v1/tasks/{id}`, data=`{task:요약+description}` | 상세 필드·ID·NULL 최종 확인 |
| 요약 | task_id 문자열, title, assignee_id 정수, assignee_name, task_status, start_date, due_date | 전송 타입·길이·NULL |
| 상태 | not_started / in_progress / submitted / approved / returned의 명시적 매핑 | 1번·3번과 코드·저장 연결 합의 필요. enum 정수 미사용 |
| 날짜 | NULL 없는 DATE·YYYY-MM-DD·DateOnly | 날짜 의미·현재 적용 마감일·연장 반영 방식 |
| 오류 | 직원 managed403, 타인 존재 상세403, 미존재 TASK_NOT_FOUND404, 일반 HTTP_404는 연결 필요 | 존재를 숨기는 상세404 정책을 사용할지 |
| 업무 | tasks: task_id BIGINT, 제목·본문·단일 task_status·날짜·current_assignment_revision·row_version·작성자·UTC기록 | FK·제약·길이·스키마 적용 |
| 배정 | task_assignments: 업무ID+배정차수 PK, 공통 사용자 FK, 배정/수락시각 | 현재 배정 포인터·향후 쓰기 트랜잭션 |
| 관리 | task_managers: 업무ID+관리자사용자ID PK | 관리 관계 등록·회수 저장 API는 후속 2번 범위 |

원래 페이지 결과/UI 확장안을 제안했지만 첫 연결은 **기존 IReadOnlyList 인터페이스를 유지하는 전체 목록**으로 개발했다. page/limit·검색·사용자 ID 등 미지원 조건은400이고 일부만 조회한 뒤 전체처럼 표시하지 않는다.

업무 API는 `REMOTEWORK_ENABLE_TASK_QUERY_DRAFT=1`에서만 지연 등록한다. 기본 새 프로세스는 업무 모델을 import하지 않아 일반 init-db가 초안 테이블을 만들지 않는다. 활성화·초기화는 삭제 가능한 개발/테스트 DB에서만 사용한다. 공유 DB에 적용하려면 1번과 migration 번호·schema version·백업/복구·기존 데이터 이관을 먼저 합의한다.

## 합의 항목별 상태

| 기존 ID | 현재 상태와 확인할 내용 | 상대 |
|---|---|---|
| C01 | 공통 소스 채택·PR 재검토/병합 완료, 그대로 재사용 | 1번·팀장 |
| C02·C03 | 조회 개발 API·HTTP 서비스 연결 완료. 경로/DTO를 공유 계약으로 고정할지는 확인 필요 | 1번·2번 |
| C04 | 지정 관리자 범위는 사용자 확정. 현재 본인 배정/지정 관리자 서버 검증 완료. 협업 포함 여부는 별도 | 1번·2번·팀장, 협업은 4번 |
| C05 | 개발 정책은 타인403·미존재 전용404. 존재 은닉404 최종 정책은 합의 필요 | 1번·2번 |
| C06 | 5개 의미는 확정. 코드·최초 저장·제출 상태 갱신 트랜잭션 합의 필요 | 1번·2번·3번 |
| C07 | 상위 검토자·반려 후 재작업·재제출 연결 합의 필요, 이번 구현 제외 | 1번·2번·3번·팀장 |
| C08 | 조회용 DATE 구현은 개발안. 날짜 기준·현재 마감일·연장·마감 후 직접 제출 합의 필요 | 1번·2번·3번 |
| C09 | 자동 검토 요청 도입/조건/중복/재실행은 질문으로 유지. 자동 결과 제출은 제외 | 2번·3번·팀장 |
| C10 | 기존 TaskQueryFailure·ApiException으로 분류, 공통 오류 구조 추가 없음 | 필요 시 1번·2번 |
| C11 | ORM·FK 격리DB 검증 완료. 공유 스키마·migration/버전·적용 책임 합의 필요 | 1번·2번, 제출 연결은 3번 |
| C12 | 격리 MySQL+실제 C# HTTP/화면 검증 완료. 공유 서버/IP·업무 입력 데이터·두 PC·웹은 미검증 | 1번·2번 |

각 합의에 결정 내용·확인한 담당자·날짜·근거 커밋/회신을 추가한다. 제안 게시나 테스트 통과를 팀 합의 완료로 바꾸지 않는다. [이전 공동 합의 목록](../1번/2026-10-16_공동합의_필요항목.md)은 당시 기록으로 보존한다.

## 담당 경계

3번의 첨부·결과물·제출·재제출·차수·검토·승인·반려·이력·상위 검토자와 상태 전환은 변경하지 않았다. 2번 업무 등록·수정·수락·연장·요청 저장도 이번 조회 구현에서 추가하지 않았다. 자동 결과 제출은 없으며 검토 요청/미확정 전환은 위 질문으로 남긴다.

파일별 변경·실행 검증·미실행 범위는 [실제 조회 개발 기록](2026-10-17_업무목록_상세_실제조회_개발초안.md)을 따른다.
