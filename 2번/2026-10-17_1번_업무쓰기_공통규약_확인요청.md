# 1번 전달 — 업무 등록·수락·마감 관리의 공통 쓰기 규약 확인 요청

업무 목록·상세의 읽기 연결 이후 등록·본인 수락·마감 관리를 준비합니다. 아래는 **쓰기에서 추가로 필요한 공통 지원 확인**입니다. [기존 M1-01~10 확정 회신](../1번/2026-10-17_업무조회_API_DB_규약확정_회신.md)과 [수신 확인](2026-10-17_1번회신_수신확인_및_조회규약반영.md)을 그대로 사용하며, 답변받은 조회 규약을 다시 결정해 달라는 요청이 아닙니다.

기준: alpha [8a652ad](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/commit/8a652adaba4a8471b2fff581f1265bf27c8ff1d3), LOG `09949823537d18bcc93c48c6529541d149d30410`. 3번의 회신·API/DB 계약은 이 기준에서 확인되지 않았습니다. 이후 새 자료가 있다면 문서·브랜치·커밋을 회신에 연결해 주세요.

후속 alpha [c96d495](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/commit/c96d495087da97f7aac3385cf048da2f23d11eb8)에는 [로컬 입력/대상 확인 준비](2026-10-17_업무등록_수락_마감_입력준비.md)만 추가했습니다. 쓰기 API/DB·상태 전환은 연결하지 않았으며 아래 확인 요청은 유지합니다.

## 이미 확인한 기준

| 구분 | 유지하는 기준 |
|---|---|
| 공통 호출·인증 | AppServices.Api·서버 루트·상대 경로·Bearer·서버 g.user를 사용합니다. 클라이언트의 사용자 ID/role은 권한 증거로 사용하지 않습니다. |
| 읽기 | M1-01~05의 GET 경로·DTO·전체 목록/정렬·본인/지정 관리자 범위·401/403/전용404 구분을 유지합니다. |
| 표현 | M1-06의 5개 소문자 상태 코드, DATE / YYYY-MM-DD / DateOnly, 별도의 UTC 기록 시각을 유지합니다. |
| DB | M1-07의 signed INTEGER 사용자·signed BIGINT 업무, 공통 Base/get_db/transaction·같은 트랜잭션 감사 이력·비활성화 이력 보존을 재사용합니다. |
| 적용 | M1-08~09의 002 번호 예약·검토/복구 게이트·현재 version1·기본 off를 유지합니다. 초안 검증은 정식 DDL 승인이나 공유 적용이 아닙니다. |
| 업무 원칙 | 배정 후 진행전→수락 시 진행중, 정식 제출 후 필수 검토, 승인완료만 최종 완료, 관리자 본인 제출은 상위 검토자 판단·자기 판단 금지입니다. 자동 결과 제출은 제외합니다. |

관리 업무 **조회** 권한은 업무별 지정 관리자만입니다. 이 관계만으로 등록·수정·재배정·마감 연장 승인 권한까지 확정됐다고 해석하지 않습니다. 업무별 쓰기 주체·허용 상태는 2번이 업무 정책으로 정리하고, 제출과 충돌하는 조건은 3번 및 팀장과 맞추겠습니다.

## 3번과 연결할 부분

[3번 수락·상태·마감 연결 요청](2026-10-17_3번_수락상태_마감_연결규약_확인요청.md)의 W3는 기존 M3 질문을 구체화한 것입니다. 초기 저장값/수락 경계, 제출·판단과 단일 상태의 원자성, 배정 차수·row_version 갱신 책임, 상위 검토자 조회, 마감/연장 조건을 3번이 답한 뒤 W1-02~05를 공동 대조하겠습니다. 1번께 3번 제출/판단 기능 구현을 요청하지 않습니다.

DATE가 확정됐어도 **업무 시간대·마감 당일의 종료 시각·지연 직접 제출·연장 반영 시점**까지 확정된 것은 아닙니다. UTC 기록 시각과 구분하고, 1번께는 합의된 업무 의미를 저장·전송할 공통 지원을 확인받겠습니다. 자동 검토 요청은 합의 필요이며 자동 결과 제출은 계속 제외합니다.

## 회신 양식과 후속 순서

기존 규약이 있으면 새 설계를 만들기보다 해당 소스/문서 링크와 적용 범위를 알려 주세요. 각 W1 항목은 **기준 수용 / 변경안 / 공통 지원 추가 필요 / 합의 필요**로 답해 주세요. 상태만 ‘확정’으로 쓰지 말고 확인 담당·날짜·근거를 남깁니다.

```text
항목 ID: W1-__
회신 상태:
결정/변경안 또는 기존 규약:
근거 문서·브랜치·커밋:
API/오류/권한/DB 영향:
1번 공통 지원 담당·예상 확인 시점:
2번·3번/팀장 공동 확인 항목:
같이 실행할 검증:
```

현재 조회 DTO에는 배정 차수와 row_version이 없습니다. 해당 정보를 쓰기 요청에서 요구한다면 조회/쓰기 준비 응답·호출부·테스트의 변경을 함께 합의해야 합니다. 화면에 보이는 담당자 표시명은 사용자 ID를 대신하지 않습니다.

진행 순서는 **2·3번 업무 쓰기/상태 경계 확인 → W1-01~05·07 공동 대조 → 2번 등록·수락·마감 저장 구현 → 격리 회귀 → 공식 환경·백업/복구 확인 후 공유 검증**입니다. 일부만 먼저 답변받으면 그 답변으로 독립 가능한 단계부터 진행합니다.

이번 전달문은 자료 대조와 질문 정리입니다. 쓰기 API/DB·버전2·공유 적용·두 PC·3번 통합을 실행하거나 완료한 기록이 아닙니다. 기존 읽기 검증 수치는 [실행기 기록](2026-10-17_업무조회_격리HTTP_통합검증_실행기.md)에서 확인합니다.
