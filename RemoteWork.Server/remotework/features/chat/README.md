# 채팅 DB 저장 - 로컬 구현, 2026-10-19

사용자 요청에 따라 초대 목록·대화방·참여자·메시지를 기존 서버 DB에 연결했다. 실제 로그인 MainForm은 HttpChatService를 사용한다. Designer/명시적 preview·기존 테스트는 메모리 서비스를 유지하며 실제 로그인 경로의 오류를 예시 데이터로 대체하지 않는다.

## 최초 준비와 실행

서버의 기존 .env에서 MySQL 접속·SECRET_KEY가 준비돼 있어야 한다. 프로그램 계정 비밀번호와 MySQL 계정 비밀번호는 별개다. 이번 변경은 계정을 생성/변경하거나 실제 DB를 초기화하지 않는다.

로컬 개발 환경의 공통 DB가 준비된 뒤 프로젝트 루트 **Init-Chat.cmd**를 한 번 실행한다. 내부 명령은 RemoteWork.Server에서 `.venv\Scripts\python.exe -m flask --app remotework chat init-tables`다. 공통 테이블이 없으면 먼저 기존 공통 초기화 절차가 필요하다. 이 명령은 chat3테이블의 누락 테이블만 만들고 기존 열을 migration하거나 공통 버전을 올리지 않는다. 기존 chat 열 구성이 다르면 중단한다. 운영/공유 DB 정식 적용은1번 검토·백업/복구·적용 승인이 별도다.

서버와 앱을 재시작하고 실제 계정으로 로그인한다. 새 방과 전송에 성공한 메시지는 같은 DB·같은 사용자로 다시 실행할 때 복원된다. Start-Demo는 명시적 별도 SQLite demo.db를 사용하므로 MySQL과 목록/계정/기록을 공유하지 않는다. 일반 API 요청에서 DDL을 실행하지 않는다.

## 사용자 기준

- 활성 직원/관리자는 활성 사용자 목록을 초대 후보로 조회한다. 본인은 자동 포함, 최소ID/이름/부서만 반환한다.
- 개인방은 상대1명, 그룹방은 상대2명이상. 서버가 로그인 본인과 활성 상대방을 재확인하고 참여자 행을 저장한다.
- 방·메시지 조회/쓰기/숨김은 해당 참여자만 가능하다. 관리자 role만으로 타인 방을 조회하지 않는다.
- 삭제는 **본인 chat_members.hidden_at만 설정**한다. 메시지/다른 참여자 행을 삭제하지 않는다. 숨긴 방은 재로그인 후에도 목록에서 빠지고, 타인이 새 메시지를 보내도 자동 복원하지 않는다. 숨긴 방 복원/실제 탈퇴는 이번 기능에 없다.
- 방 참가자 이름·부서는 생성 당시 snapshot, 메시지 작성자 이름은 전송 당시 snapshot이다. 비활성 계정을 과거 이력에서 자동 삭제하지 않는다.
- 메시지는 최대2000자·서버 UTC 기록. 공개ID는UUID, DB seq로 전송 저장 순서를 보존한다.
- UUID를 사용해 같은 요청의 재시도 중복을 확인한다. 동일ID/다른본문·다른방·다른작성자는409다. 성공 후 명시적으로 같은 내용을 새로 보내면 새 메시지다. 자동 전송 재시도는 하지 않는다.

## 로컬 API/DDL 계약과 상태

`GET /api/v1/chat/participants`: 기존 후보 페이지.
`GET /api/v1/chat/rooms`: 본인 숨김 제외 방, UUID after 커서·limit100.
`POST /api/v1/chat/rooms`: room_id(UUID)/title/is_group/participant_ids, 서버 본인 포함.
`GET /api/v1/chat/rooms/{id}/messages`: seq 문자열 after 커서(초기0)·limit100.
`POST /api/v1/chat/rooms/{id}/messages`: message_id(UUID)/content.
`POST /api/v1/chat/rooms/{id}/hide`: 빈 body, 본인 목록 숨김.

성공은 공통 envelope, 미인증401·입력400·참여방아님/본인숨김404·요청충돌/선택불가409·테이블미준비503을 사용한다. 서버/DB 장애를 미존재로 숨기지 않는다. 쓰기는1번 authenticated_transaction을 재사용해 현재 접속/사용자 재확인과 공지/사용자관리와 동일한 guard 순서를 유지한다. 공지/업무 모델·DB 기록·schema version1은 변경하지 않는다.

chat_storage.mysql.sql은 **번호 미지정 개발 검토안**이다. 공동 migration 번호·SQL/FK·보존/공유 배포는1번 검토 전이며 기존002/003/004를 수정하지 않았다. 사용자 승인 기능의 로컬 구현과 팀 전체 계약 수용·정식 적용을 구분한다.

클라이언트는 모든 페이지를 성공적으로 받은 뒤 화면에 표시한다. 중간 실패를 일부 기록으로 성공 처리하지 않는다. 메인 폼은 로그인 사용자를 기준으로 서비스를 생성하고 공통 ApiClient의 인증/오류/세대 취소 처리를 재사용한다. 접속 정보가 조회 도중 바뀌면 재조회하도록 안내한다.

이번 범위는 영속 저장/재조회다. 실시간 push·새 메시지 자동 알림·주기적 자동 갱신·첨부파일·숨김방 복원 UI는 구현하지 않았다. 다른 참여자의 새 대화는 방 재선택 또는 채팅 메뉴 재진입 시 불러온다. 임시 작성 초안은 전송 전에는 DB에 저장하지 않는다. 기존 메모리 예시 대화는 이관하지 않는다.

## 검증 상태

사용자가 직접 테스트하겠다고 요청해 이번 저장 기능의 빌드·서버/DB 실행·통합 테스트는 하지 않았다. Python 구문/수정 범위는 정적으로 확인하고 실제 기능 검증과 구분해 보고한다. 앞선 후보조회6/40 등은 이전 작업 결과이며 이번 저장 기능 결과로 사용하지 않는다.
