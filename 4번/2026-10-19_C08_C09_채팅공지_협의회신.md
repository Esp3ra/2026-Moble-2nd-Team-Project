#### C09/N4-08/R04 시작 경계·페이지 — 1번 기술 방향 수용 / 구체안은 협의사항

## C08 - 수용한 내용과 실제 코드 차이

1. **005 정리 완료:** 1번 PR #25 head2173492의 SQL과 안내를 그대로 포함했다. SQL blob은 `ba99da28aa494e3d45394c5eec7f5ff67900d877`, 안내 blob은 `77f43d37496d1718e0bd1952f9c75f7aedb77512`로 현재 원본 alpha에서도 일치한다. 기존 `chat_storage.mysql.sql`은 제거했고, 005와 번호 없는 SQL을 함께 실행하는 경로는 남기지 않았다.
2. **ORM 정합성:** chat/models.py의 세 테이블에 InnoDB·utf8mb4·utf8mb4_unicode_ci를 명시했다. 공개 UUID VARCHAR36, seq signed BIGINT, users signed INTEGER FK, UNIQUE/인덱스·cascade 없음 기준을 유지한다.
3. **초기화·기존 DB:** chat off 새 프로세스에서 공통 DB 준비 → 새 개발 채팅 테이블을 005 SQL 또는 Init-Chat 중 한 방법으로 준비 → 서버 flag 별도 활성화 순서를 수용한다. CLI 열 이름 검사만으로 타입·NULL·default·FK·인덱스·엔진·collation 호환을 인증하지 않는다. 기존 테이블은 자동 ALTER/DROP/덮어쓰기하지 않고 물리 차이와 데이터 보존을 먼저 검토한다. 기능 flag와 테이블 준비·공통 schema version1은 별개다.
4. **UUID·권한:** CaptureSession과 현재 참여·활성·숨김 재검사, 같은 TX 감사, 동일 UUID/동일 요청의 단일 효과를 유지한다. UUID나 본문을 바꿔 자동 재전송하지 않는다. 앱 재시작 후 불명 UUID 복구는 아직 제공하지 않는다. 별도 공통24시간 receipt를 이 채팅에 중복 강제하지 않는다는 1번 판단을 수신·수용한다.
5. **본인 숨김:** 자신의 hidden_at만 변경하고 상대 기록과 메시지를 삭제하지 않는다. 새 메시지로 숨김을 복원하지 않는다. 메시지·감사는 자동 삭제하지 않는다. 복원/탈퇴·운영 보존 기간·정리 실행자는 별도 합의 대상이다.

공통 ApiClient/auth·업무/결과·장치 인터페이스를 이번 문서 작업에서 수정하지 않는다. 공유 DB 적용 승인·환경/백업·복구 담당·실행 시점은 C01의 대표 협의로 연결하며 이 문서에서 별도 규칙을 만들지 않는다.

| 로그아웃·부서 변경 | 이전 세대 요청/예약 팝업을 취소. 서버의 현재 사용자·부서·활성으로 표시 직전 재검사. 부서 변경 이전 대상은 큐에서 제외하고 새 부서 과거 공지는 자동 소급하지 않는 안 | 부서 변경 시 새 수신 경계·보류 큐 재계산을 1번/팀장 확인. 표시명으로 부서를 추측하지 않음 |
| 기존 공지의 고정 변경 | 1차 범위는 “새로 등록될 때 고정된 공지”로 제한하는 안. 나중에 고정으로 바꾼 기존 공지를 재알림할지는 별도 결정 | 고정 해제·재고정·대상 수정이 새 알림 사건인지 결정. 현재 수정 API를 새로 있다고 가정하지 않음 |
| 표시·간격 | 작업을 계속할 수 있는 알림과 상세 보기 연결, 동시에 여러 건이면 큐로 순차 처리하는 방향을 제안. 조회 간격은 공통 인증·부하·최소 지연과 함께 검토 | 채팅1초 간격이나 과거15초를 공지의 확정 규약으로 복사하지 않음. 실제 공지 팝업 형태·닫기/재표시·표시 시간·수신 간격은 별도 확인 |
| 명시 확인 | 닫기/표시와 “확인”을 구분. 확인 버튼에서 서버 본인 사용자·UTC로 기록하고 서버 성공 뒤에만 확인 완료. 실패/불명 결과는 미확인 또는 결과 확인 필요로 유지 | 중복 확인의 동일 성공 응답·삭제와의 경합·현재 접근 권한·확인 취소 허용 여부를 공동 결정 |
| 확인 키·수정 후 재확인 | 현재 공지 수정 기능이 없는 1차안은 notice_id/user_id 유일성. 재확인이 필요해지면 명시적 공지 revision과 유일키 확장안을 먼저 설계 | 단순 조회/고정 변경을 새 버전으로 자동 간주하지 않음. revision 타입·증가 조건·확인 보존·FK·migration 번호는 미확정 |

제안된 pending 조회·confirm 저장 경로는 아직 정식 API가 아니다. 구체 URL·필드·cursor·응답/오류·서명/멱등 도구·테이블/번호는 1번 검토와 팀장 정책 회신 후 별도 코드 PR/DDL로 준비한다. 이번 협업 요청 알림(작은 팝업) 논의도 공지 팝업 규약에 자동 전용하지 않으며 업무 참여·수락 권한은 2번과 별도 접점으로 남긴다.
