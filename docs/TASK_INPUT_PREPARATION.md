# 2번 업무 등록·수락·마감 입력 준비

## 2026-10-17 W1 연결 후속

[후보·쓰기 준비 연결](TASK_WRITE_PREPARATION.md)을 추가했습니다. 실제 로그인된 업무 화면에서는 등록/수정 창의 별도 버튼으로 담당자·업무 관리자 후보와 현재 쓰기 문맥을 조회·선택할 수 있습니다. 기본/미리보기 생성자는 미연결 상태를 유지하며, 기존 CheckedInput은 변경하지 않고 선택값은 별도 PreparedSelection에 보관합니다. 아래 담당자 미연결 설명은 초기 로컬 입력 준비 범위의 기록입니다. 실제 업무 저장·수락·마감 변경은 아직 연결하지 않았습니다.

최신화: 2026-10-17 · 로컬 입력/대상 확인·불변 확인값 구현 · 서버 저장 규약은 합의 필요

1번이 수용한 [기존 조회 계약](TASK_QUERIES.md)을 유지하며, 조회 성공한 업무를 등록·수정 입력 준비, 수락 대상 확인, 마감 연장 입력 준비에 연결한다. 이 화면의 입력 확인은 등록·수정·수락·접수나 실제 마감 변경이 아니다. HTTP 쓰기·DB 저장·상태 변경은 연결하지 않는다.

## 동작

| 화면 | 현재 가능한 동작 | 서버 연결 전 항목 |
|---|---|---|
| 업무 등록 | 빈 입력에서 제목·내용·시작일·마감일을 작성하고 기본 형식 확인 | 배정 가능한 사용자 조회·관리자 지정·등록 API·초기 상태 저장 |
| 업무 수정 준비 | 현재 선택의 성공 상세에서 제목·내용·담당자 표시명·날짜 표시, 로컬 기본 형식 확인 | 사용자 ID·배정 차수·수정번호·수정/재배정 허용 조건·PATCH |
| 업무 수락 대상 확인 | 현재 선택 업무의 ID·제목·담당자·5단계 상태·날짜를 읽기 전용으로 표시 | 수락 API·현재 배정/세션/버전 검사·진행중 저장·재시도 규약 |
| 마감 연장 입력 준비 | 실제 대상·현재 마감일 표시, 희망일·사유 입력 형식 확인 | 신청 가능한 상태·연장 가능한 날짜·신청/판단 API·실제 마감 변경 |

등록/수정은 공백 제목·현재 모델의200문자 범위·필수 날짜·시작일보다 이른 마감일을 로컬에서 검사한다. 문자 수는 UTF-16 코드 단위가 아닌 Unicode 코드 포인트로 센다. 내용의 빈 문자열을 임의로 금지하지 않는다. 최초 날짜는 미선택이며 예전 고정 날짜를 입력값으로 간주하지 않는다. 입력 확인 후에도 창과 값은 유지하고 저장·전송 미연결을 안내한다. 입력이 바뀌면 이전 확인 문구를 초기화한다.

연장은 희망일을 명시적으로 선택하고 사유가 공백이 아닌지만 검사한다. 현재 마감일보다 늦어야 하는지, 어떤 상태에서 신청 가능한지, 사유 최대 길이 등 미합의 정책은 추가하지 않는다. 입력 형식 확인 성공은 연장 가능·접수 완료·마감 변경을 뜻하지 않는다.

수락 대상 확인 창에는 닫기만 제공한다. 화면에서 상태를 변경하거나 수락 가능 여부를 서버 판단처럼 확정하지 않는다. 관리자 본인 업무도 같은 방식으로 대상을 확인한다.

## 확인된 로컬 입력값

`Preparation/TaskInputDrafts.cs`의 불변 record는 입력 확인 성공 시점의 값을 보관한다. 서버 요청 DTO·DB 모델·배정/버전 계약이 아니며 HTTP 직렬화나 저장에 사용하지 않는다.

| 폼의 CheckedInput | 보관하는 값 |
|---|---|
| TaskEditForm | TaskBasicInputDraft: 원본 TaskId(새 등록은 null), 제목·내용 원문, 시작일·마감일 DateOnly |
| DeadlineExtensionForm | DeadlineExtensionInputDraft: 원본 TaskId·현재 마감일, 희망 마감일 DateOnly·사유 원문 |

확인 전·검사 실패 후에는 null이다. 입력 변경 시 이전 확인값을 무효화하고, 값을 읽을 때도 현재 입력·원본 문맥과 대조한다. DateTimePicker의 Checked를 코드로 바꿔 변경 이벤트가 발생하지 않는 경우에도 이전 확인값을 반환하지 않는다. 다시 값을 확인하려면 입력 확인을 명시적으로 눌러야 한다. 이전 record를 이미 읽은 호출자의 값은 불변이므로 변하지 않으며 저장 권한이나 최신 서버 상태를 보장하지 않는다. 제목·내용·사유의 공백을 임의로 잘라내지 않는다.

확인 후에도 모달을 성공 결과로 닫거나 업무 상태를 바꾸지 않는다. 사용자 ID·배정 차수·수정번호·idempotency key는 합의 전 추측해서 추가하지 않는다.

## 선택 문맥과 날짜 보존

TasksControl은 현재 행의 상세 조회가 성공하고 ID가 일치할 때만 수정·수락·연장 대상 버튼을 활성화한다. 선택/범위/상태 변경·새 조회·로딩·상세 실패·인증 실패·취소·빈 목록·종료에서 이전 상세 캐시를 지운다. 늦게 도착한 응답은 새 선택의 준비 문맥이 될 수 없다. 모달 입력은 불변 TaskDetail을 복사해 표시하며 원래 업무를 수정하지 않는다.

기존 조회 DTO에는 담당자 ID·배정 차수·수정번호가 없다. 표시명으로 ID를 추측하거나 서버 쓰기 DTO를 임의로 확장하지 않는다. 담당자 선택지는 합의 전 비활성으로 두며 공통 관리자용 GET /users를 배정 허용 목록으로 전용하지 않는다. 첨부와 검토·제출 기능은 3번 계약에 맡긴다.

DateOnly의 범위는 WinForms DateTimePicker보다 넓다. 조회 날짜가 Picker 범위 밖이면 원본 날짜를 표시하고 해당 입력과 입력 확인을 비활성화한다. 다른 날짜로 자동 보정하지 않는다. 날짜를 UTC 자정으로 변환하거나 임의의 마감 시각을 만들지 않는다.
