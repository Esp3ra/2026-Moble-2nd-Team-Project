# 라파 지문 비교 코어 — 연결 전 준비

5번 소유 fingerprint_match.compare_fingerprint는 기존 FingerprintService의
센서 객체·잠금·중지 신호·OLED를 빌려, 새 손가락 입력 한 번을 기대 슬롯과 비교한다.
새 UART를 열거나 기존 등록·scan·조도 실행 코드를 변경하지 않는다.

이 함수는 **회원 본인인증 또는 출퇴근 완료 판정이 아니다.**
서버가 검증한 현재 challenge/매핑에서 기대 슬롯을 정하고 채취를 승인하는 어댑터,
목적·현재 접속·만료·재전송·단일소비와 서명 결과를 검증하는 서버/C# 계약은
1번과 대조 후 별도로 연결해야 한다. 슬롯을 PC 입력이나 이름표로 정해서는 안 된다.
기존 등록 ticket·등록 키 설정을 인증에 재사용하도록 배포한 코드가 아니다.

## 로컬 동작

- 이전 손가락 제거 후 새 입력·특징 추출·검색을 각각 한 번 진행한다.
- 결과는 matched, different_finger, unregistered, busy, timeout,
  cancelled, sensor_error다. 오직 기대 슬롯과 정확히 일치할 때만 슬롯을 반환한다.
  다른 사람 슬롯·이름·점수·생체 원본을 내보내지 않는다.
- 공통 단조시계 예산 안에서 동작하고 각 센서 명령 전후에 취소/종료·기한을 확인한다.
  지연된 센서 성공을 그대로 반환하지 않는다. 이 예산은 서버 challenge TTL이 아니다.
- OLED는 일치하더라도 ‘지문 일치 / 서버 확인 필요’까지만 표시한다.
  센서 오류 문자열을 출력하지 않고, OLED 오류 때도 센서 재시도나 잠금 누수가 없다.
- 같은 잠금을 사용하므로 기존 등록/scan과 동시에 센서를 사용하지 않는다.
  조도 수신은 계속 가능하며 비교 안내를 조도 화면으로 덮지 않는다.
- 템플릿 등록·삭제/읽어내기, 로컬 DB, 네트워크·키·서명, HTTP 경로를 추가하지 않는다.

## 검증과 적용 상태

    python -X utf8 -W error::ResourceWarning -m unittest discover -s Devices/RaspberryPi -p test_fingerprint_match.py -v

기대/다른/미등록 지문·중복 소유·기존 손가락 제거·단일 예산·취소/늦은 성공·드라이버 오류·
잘못된 타입·OLED 실패·scan409·조도 병행을 가짜 센서/실제 공유 서비스로 검사한다.
실제 센서 비교 및 로그인/서버 회원 검증 검사는 별도다.

현재 코어는 제품 실행기에서 호출하지 않으며, 실제 Pi 서비스·설정·저장 지문과
서버/API·DB·로그인·출퇴근 화면에는 적용하지 않았다. 등록·재인식의 앞선 사용자
실물 성공을 이 새 코어의 실물 검증으로 재사용하지 않는다.
