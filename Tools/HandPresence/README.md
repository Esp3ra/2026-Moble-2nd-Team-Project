# Windows USB 웹캠 손 검출 시연 — 5번

얼굴 대신 손·몸 방향으로 촬영해 원격 근무 재석의 보조 신호로 쓰려는 요구 중 **손 검출을 먼저 확인하는 로컬 시연**입니다. [C# WinForms 연결 안내](../../RemoteWork.WinForms/Features/Attendance/README.md)에 따라 근태 화면에서 별도 활동 상태 확인 창을 열 수 있습니다. 기존 Tk 창도 독립 실행 가능합니다. 몸통 검출·공통 회원·근태 저장은 미연결이며 Pi·메가·OLED 코드는 변경하지 않습니다.

## 준비·실행

Windows Python3.13이 필요합니다. 이 PC에서는 Python3.13.15로 설치와 테스트했습니다.

1. 웹캠을 PC에 연결하고 **손·키보드 방향으로 아래로 향하게 고정**합니다. 얼굴·배경을 촬영하지 않으려면 촬영 각도로 먼저 제외해야 합니다.
2. Windows 카메라 앱과 웹캠을 사용하는 다른 프로그램을 닫습니다.
3. 최초 한 번 `Setup-Hand-Presence.cmd`를 실행합니다. 이 폴더의 `.venv`에 패키지, `models/`에 공식 Google 모델을 내려받습니다. 기본 Python/다른 가상환경은 변경하지 않습니다. 설치에는 인터넷이 필요합니다.
4. `Start-Hand-Presence.cmd`를 실행합니다. 창을 여는 것만으로 웹캠을 켜지 않습니다.
5. 카메라 번호0, DSHOW로 시작하고 **카메라 시작**을 누릅니다. 다른 웹캠이 선택되면 중지한 뒤 번호1 등으로 직접 바꿉니다. 장치를 자동으로 순회해 열지 않습니다.
6. 화면 범위(%)를 바꾸고 **영역 적용**을 누르면 새 영역의 이력부터 확인합니다. 기본은 전체 가로·상단35%를 제외한 아래쪽입니다. 표시도 해당 영역만 사용합니다.
7. 종료할 때 **중지**를 누르거나 창을 닫습니다. 정상 중지에서는 카메라와 모델을 해제합니다. 드라이버 입력이 멈춰 중지 요청 중이라면 이전 결과를 숨기고 실제 입력 종료를 기다립니다.

열리지 않으면 카메라 앱 종료, USB 연결과 Windows 카메라 권한, 번호를 확인합니다. 필요하면 중지 후 backend를 MSMF로 바꿔 직접 다시 시작합니다. 모델이 없거나 해시가 다르면 카메라를 열기 전에 실패합니다. 검증되지 않은 파일로 자동 대체하지 않습니다.

## 상태의 의미

사용자 요청에 따라 Tk와 C# 화면 모두 활동 중·자리 비움·확인 대기·카메라 연결 끊김의 표현을 사용합니다. C#은 같은 PC의 Python 모델을 자식 프로세스로 실행하며 선택 영역 미리보기와 상태만 전용 파이프로 받습니다. 표시를 출퇴근 기록에 자동 반영하지 않습니다.

| 화면 | 의미 |
|---|---|
| 활동 중 | 현재 분석 영역에서 손을 검출. 최대2개. 움직임 차이가 없어도 매 프레임 검출 수행 |
| 자리 비움 | 손이 검출되지 않은 연속 시간 표시. 영역 밖·가림·검출 실패일 수 있으며 이석/퇴근/결근으로 판정하지 않음 |
| 카메라 연결 끊김 / 카메라 확인 필요 | 연결·모델·영상·분석 실패. 재석 판단 불가로 표시하고 오래된 영상/결과를 숨김 |
| 카메라 연결 지연 | 5초 이상 새 결과 없음. 이전 영상을 숨김. 오류/지연을 미검출과 구분 |

몸만 보이고 손이 안 보이면 현재 버전에서는 손 미검출입니다. 사람 본인인지 식별하지 않으며 손이 있다는 것만으로 실제 근무나 대리 근무 여부를 보장하지 않습니다. 검출 신뢰도0.5는 모델 설정이고 재석 정확도/신원 확률이 아닙니다.

## 영상 범위와 처리

카메라 원본 프레임은 장치에서 PC 메모리로 들어온 뒤 설정 영역으로 자릅니다. **영역 자르기는 카메라의 물리적 촬영 범위를 바꾸거나 얼굴/배경을 자동 제거하는 기능이 아닙니다.** 선택 영역 안에 얼굴/배경이 들어오면 그대로 보일 수 있습니다. 촬영 각도를 먼저 맞춥니다.

모델에는 잘라낸 RGB 영상만 전달하고 UI에는 같은 영역과 손 경계 상자만 표시합니다. 원본은 UI 대기열에 넣지 않습니다. UI 대기열은 최신 잘린 영상1개만 유지합니다. 중지·오류·지연·영역 변경 시 이전 표시를 지우고 이전 세션/영역의 늦은 프레임을 버립니다.

프로그램은 영상·사진·손 특징점·검출 이력을 파일에 저장하지 않고 서버/API로 보내지 않습니다. WinForms 모드에서 선택 영역 JPEG는 같은 PC의 소유 C# 창에만 메모리 파이프로 전달합니다. 얼굴 모델·얼굴 특징 추출·마이크 입력도 사용하지 않습니다. 실행 중 네트워크 호출이 없으며 별도 설치 스크립트만 패키지/모델을 내려받습니다. 공통 사용자의 본인 확인·근태 기록에 이 결과를 신뢰하도록 연결하지 않습니다.

## 구현과 모델

- MediaPipe Hand Landmarker의 **IMAGE 모드**로 각 프레임을 검사하므로 움직임 차이만으로 판정하지 않습니다. 정지한 손의 실제 검출 성능은 촬영 각도·크기·가림·조명에 따라 확인해야 합니다.
- OpenCV로 지정한 카메라 하나만 열며 수신/모델 추론은 별도 스레드, Tk 화면 처리는 메인 스레드에서 수행합니다.
- Python3.13.15, MediaPipe1.1.1, OpenCV contrib5.0.0.93(런타임5.0.0), Pillow13.0.0을 사용했습니다. 직접 의존성 버전은 requirements.txt에 고정했습니다.
- 모델 URL은 [공식 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)의 다운로드 링크입니다. SHA256 `fbc2a30080c3c557093b5ddfc334698132eb341044ccee322ccf8bcf3607cde1`을 검증합니다. 모델·가상환경·개인 설정은 Git에서 제외합니다.
- 참고: [Python Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python), [OpenCV VideoCapture](https://docs.opencv.org/4.x/d8/dfe/classcv_1_1VideoCapture.html). 모델의 출처·이용 조건은 해당 공식 안내를 따릅니다.

## 검증과 실제 사용 체크

이 폴더에서:

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_hand_presence test_winforms_bridge
.\.venv\Scripts\python.exe -m py_compile hand_presence.py presence_core.py download_model.py
```

자동 테스트24개 통과: 기존16개와 R23-01 추론 지연·queue 지연/복구, WinForms용 JPEG/오래된 영상 제외·encoding 지연·소유 프로세스 EOF/중지·stdio 합성 프레임·시작 단계 전달 검증. 물리 카메라는 열지 않습니다. C# 회귀에는 별도 새 Python 프로세스의 실제 bridge CLI 초기화 검사를 포함합니다.

실제 공식 모델을 로드해 합성 검은 영상 추론에서 손0개 반환을 확인했습니다. 사용자는 실제 카메라 인식이 정상이라고 확인했습니다. 정지 손·손 제거·조명/가림·USB 분리 정확도를 각각 확인했다는 근거는 아직 없으며 작성자가 실제 카메라 영상을 열어 검사하지 않았습니다. 카메라를 자동으로 켜 사용자 영상을 수집하지 않았습니다.

사용자 확인 순서:

1. 손을 화면 범위에 넣으면 활동 중으로 표시되는지 확인.
2. 손을 수초 가만히 두어도 검출이 유지되는지 확인.
3. 손을 빼면 자리 비움과 손이 확인되지 않은 시간이 표시되는지 확인.
4. 중지하면 영상이 사라지고 카메라 사용 표시가 꺼지는지 확인.

확인 결과 이후 몸통 검출 또는 더 맞는 촬영 영역을 검토합니다. 임의 시간 기준의 자동 이석·결근 정책과 공통 서버 저장은 확정하지 않습니다. 출퇴근 기록·연차 신청/승인은 별도 5번 구현 대상입니다.
