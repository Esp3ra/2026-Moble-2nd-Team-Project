# Windows 장치 점검 도구

5번 [라파 독립 API](../../Devices/RaspberryPi/README.md)를 조회하는 Python/Tk 화면입니다. 기존 공통 WinForms·회원 로그인·근태 저장을 변경하지 않습니다. Python 표준 라이브러리만 사용합니다.

## 실행

1. Pi의 `pi_api.py` 또는 자동 실행 서비스를 켭니다.
2. Windows에서 이 폴더의 `Start-Device-Check.cmd`를 더블클릭합니다. 또는 `python device_check.py`를 실행합니다.
3. 서버 주소를 실제 Pi의 `http://주소:8080`으로 바꿉니다. 기본 `raspberrypi.local`은 예시이며 장치의 실제 호스트명/IP를 사용합니다.
4. **연결 / 다시 연결**을 누릅니다.
5. 조도 상태를 확인하고 **지문 인식 요청** 후 OLED 안내를 따릅니다.

Python의 Tk 지원이 필요합니다. Windows Python 3.14.7 / Tk9.0에서 확인했습니다. Pi 하드웨어 의존 패키지는 Windows에 설치하지 않습니다.

## 동작과 제한

- `/health`, `/motion`을 한 작업 스레드에서 순서대로 조회하고 완료 후1초에 다시 조회합니다. GET 응답 대기는 요청별 최대3초입니다.
- 지문은 버튼으로만 POST하며 응답 대기는45초입니다. 자동 재요청하지 않습니다. 처리 중 버튼/주소 변경을 잠그며 조도 조회는 계속합니다.
- 화면에 현재 센서값·가림 여부와 최근 변화 이력을 따로 표시합니다. 데이터 오류나 응답 지연 시 이전 값을 숨깁니다.
- 센서가 끊겨503이 나도 API에 도달하면 지문 요청은 별도로 사용할 수 있습니다.
- 주소 변경 후 이전 대상의 늦은 응답은 버립니다. 통신 실패를 빈 데이터나 인증 성공으로 대체하지 않습니다.
- 지문 결과는 슬롯·표시 이름·센서 점수이며 **회원 계정 일치 확인 전**으로 표시합니다. 디스크에 저장하지 않습니다.
- 미등록200/사용 중409/시간 초과408/센서 오류500을 구분합니다. 클라이언트 응답 시간이 초과해도 Pi에서 요청이 취소된 것은 아니므로 OLED를 확인합니다.
- 이름표·지문 원본·계정·DB·출퇴근 연계는 포함하지 않습니다. 그림자 모의실험을 재석·이석으로 판정하지 않습니다.

```powershell
python -m unittest -v test_device_check
```

자동 검증은 응답 계약·임시 HTTP 서버·Tk 화면 상태/작업 스레드 경로입니다. 사용자 확인으로 기존 도구의 실제 PC→Pi 조회·지문 요청·조도 표시도 정상 동작했습니다. 게시본에서는 개인 PC 주소를 기본값에서 제외했으므로 실행할 때 실제 Pi 주소를 입력합니다. 해당 게시본의 전체 재배포/장시간 시험 완료와 구분합니다.
