# 18. 합의 문서 최신화와 Word 정리

- 기록일: 2026-10-16
- 대상: `DOCX` 브랜치의 기준 Word, 2번 구현계획서와 문서 목록
- 순서: 같은 날 17번 알파 동기화에 이어 문서 갱신 결과를 기록한다.

## 변경 전과 후

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 업무 상태 | 이전 상태 표현과 진행률 항목이 남아 있었음 | 진행전·진행중·제출완료·승인완료·반려완료의 단일 5상태, 우선순위·숫자 진행률 제외 |
| 제출과 검토 | 관리자 본인 업무와 모든 제출의 검토 원칙이 불명확했음 | 직원·관리자의 모든 정식 제출·재제출은 필수 검토, 관리자 본인 제출본은 상위 검토자 판단 |
| 마감 자동 처리 | 자동 결과 제출로 읽힐 수 있는 표현이 있었음 | 자동 결과 제출 제외, 자동 검토 요청의 도입·조건은 합의 필요 |
| 현재 구현 범위 | 화면 뼈대 기준과 이후 조회 준비 범위가 혼재했음 | 읽기 인터페이스·명시적 테스트 대역·비동기 화면 상태 준비와 실제 서버 연결을 구분 |
| Word 목록 | 기준본 외 이전 사본 3개가 함께 있었음 | 최신 기준 Word 1개만 문서 폴더와 브랜치에 유지 |

## 기준 문서와 계획서

- 기준본은 `DOCX/원격 근무용 업무 처리 확인 시스템.docx`이다.
- `DOCX/2번_업무_상태_마감_구현계획.md`도 같은 합의와 현재 범위로 동기화했다.
- 기존 본문 148문단 중 127문단을 보존하고 합의와 모순되는 21문단을 정리했다.
- 기존 표 8개의 행·열 구조를 유지하고 필요한 문구만 수정했다.
- 최신 합의, 이번 조회 준비 범위와 공통 규약 질문을 14문단으로 추가해 전체 162문단이 됐다.
- 반려 후 작업 복귀 시점, 상위 검토자 매핑, 마감 세부 조건과 공통 API·DB 계약은 합의 필요로 남겼다.

## 첨부 조회와 실제 동작 범위

- 업무 행 선택·상태 필터 조건 전달과 상세 응답 표시 흐름은 명시한 테스트 대역으로 확인한다.
- 첨부 영역은 3번 계약이 미연결이므로 목록을 비우고 조회 연결 필요 안내만 표시한다.
- 첨부 목록을 조회·표시하는 기능이 완성된 것으로 읽힐 수 있던 Word와 계획서 표현을 교정했다.
- 기본 실행은 서버 미연결이며 실제 HTTP·MySQL·인증·서버 권한 검증 완료를 뜻하지 않는다.
- 등록·수락·제출·판단 같은 업무 변경 기능과 자동 결과 제출을 추가한 작업도 아니다.

## 사본 정리와 검수

- 이전 Word 사본 3개는 로컬 `DOCX` 폴더와 문서 브랜치의 최신 파일 목록에서 제거했다.
- 편집 전 Word 4개는 문서 폴더 밖에 보관하고 원래 SHA256과 백업 해시가 같은지 확인했다.
- 이전 사본은 별도 감사 보관하며, 최신 문서 목록에 중복 게시하지 않는다.
- 수정 Word를 PDF와 PNG로 렌더링해 14쪽 전체의 글자·표·줄바꿈을 검수했다.
- 최종 첨부 문구 보정 후 13쪽 PNG는 앞선 검수본과 해시가 같았고, 변경된 14쪽은 직접 다시 검수했다.
- 최종 정본과 렌더링한 후보 파일의 SHA256도 일치했다.

## 게시 확인과 근거

- `DOCX` 게시 커밋: `5ee0998b81c6519b60fd380ac46c719d67a63d80`.
- 원격 파일은 문서 7개와 루트 `README.md` 1개로 총 8개이며, Word는 1개다.
- 정본 SHA256: `17634df83508cafbdf0799a3c6fe00518aa57acc0a63fad6575b394e756d7ee8`.
- 원격 문서 blob과 로컬 문서의 내용·해시가 일치함을 확인했다.
- 변경 전 근거: `before-local-manifest.json`, `before-publishing-manifest.json`, `before-refs.txt`.
- 편집·검수 근거: `document-edit-report.json`, `document-final-qa.json`, `legacy-cleanup.json`.
- 게시 근거: `published-verification.json`. 감사 파일과 백업은 원격 문서 목록에 포함하지 않았다.
- 문서 갱신·게시를 명시적으로 요청받았을 때만 `DOCX` 브랜치를 게시하는 원칙을 유지한다.
