# 로컬 DOCX 폴더의 코드 게시 제외 기준

정리일: 2026-10-16 · 원격 게시 완료 기록

[변경 기록 목록으로](../../README.md) · [15. DOCX 브랜치 분리](15_DOCX_브랜치_분리.md)

문서 브랜치를 분리한 뒤, 코드 푸시에 로컬 문서가 다시 포함되지 않도록 게시 기준을 정리했다.
아래 커밋을 alpha에 게시하고 원격 파일과 로컬 게시본이 일치함을 확인했다.
기존 15번까지의 기록은 당시 이력으로 보존한다.

## 반영한 변경

- `.gitignore`에 루트 문서 폴더와 하위 파일을 제외하는 `/DOCX/` 규칙을 추가했다.
- README에 코드와 문서의 게시 기준을 추가하고 alpha와 0.0.2V의 차이를 명시했다.
- 로컬 프로젝트에도 같은 `.gitignore`와 README를 적용했다.
- 변경 파일은 `.gitignore`, `README.md` 2개이며 코드·프로젝트·솔루션·미리보기는 변경하지 않았다.

| 항목 | 게시한 값 |
|---|---|
| alpha 게시 커밋 | `2cd1a32724ecec8c21cd8ddd659dbbf30d43dcaf` |
| 이전 alpha 커밋 | `a83f8ed7b282aba7b4fe63bf72f6a2833e50fe6d` |
| 이번에 유지한 참조 | `0.0.2V` 태그, `DOCX` 브랜치 |

## README에 반영한 게시 정책

- 별도 `DOCX` 브랜치는 사용자가 문서 게시·갱신을 요청했을 때만 갱신한다.
- 코드 푸시와 함께 로컬 `DOCX/`를 자동 업로드하지 않으며 문서는 로컬에 보관한다.
- `LOG` 기록과 `DOCX/` 밖의 작업 관련 Markdown·소스·미리보기는 각 브랜치의 범위에 맞춰 게시할 수 있다.
- 새 코드 브랜치와 다른 기준에서 만든 코드 브랜치에도 `/DOCX/` 제외 규칙을 유지한다.
- 매 푸시마다 해당 브랜치 README의 목적·실제 구현 범위·파일 위치·확인 결과를 최신화한다.
- 코드 게시 전 `git ls-files -- DOCX/`로 추적 파일이 없는지 확인하고 강제로 추가하지 않는다.

## 검증과 게시 후 확인

근거는 `policy-checks.json`, `prepared-publication.json`, `alpha.diff`, `alpha-published-verification.json`이다.
DOCX 경로 12개가 무시되고 일반 작업 경로 7개는 허용되며, 추적 중인 DOCX 파일은 0개임을 확인했다.
로컬 문서 10개는 불변이고, 로컬과 게시본의 제외 규칙·README가 일치함을 확인했다.
이번 코드 게시에서는 alpha만 갱신했으며 0.0.2V와 DOCX 브랜치는 유지했다.
원격 alpha의 커밋·파일 blob이 게시본과 일치하고 변경 파일이 2개뿐임을 재확인했다. 코드 게시 시 main·LOG·모든 태그·DOCX 브랜치의 참조가 동일함도 확인했다.
이 후속 LOG 기록과 README로 최신 alpha 커밋과 게시 기준을 안내한다.
