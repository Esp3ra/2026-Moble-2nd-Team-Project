# 결과물 목록과 상세 화면 정리

기록일: 2026-10-16

이 문서는 결과물 화면의 배치 수정과 최신 로컬본의 표시 구성을 기록한다.
5개 상태는 [업무 상태 정의](08_업무상태_5단계_통일.md), 관리자 본인·검토 범위는 [관리자 화면 구분](09_관리자_본인업무_수락과제출.md)에서 다룬다.

## 제출·검토 목록 확대

직원 결과물과 관리자 결과물 화면에서 상단 목록을 확대했다.
기존 3개 고정 예시 행에 1개를 추가해 각 목록에 4개 항목을 표시한다.
목록 아래의 상세·반려 사유·첨부 자료·버전 이력 영역은 높이를 줄였다.
`ReviewsControl.Designer.cs`의 본문 행 비율은 상단 62%, 하단 38%로 조정했다.
목록 영역의 최소 높이와 하단 여백을 함께 조정해 기본·최소 창 크기에서 4행을 확인할 수 있게 했다.
관리자 범위 선택은 목록 카드 제목행에 배치해 기존 목록 도구줄과 4행 표시 공간을 유지했다.

## 하단 상세와 첨부 자료

왼쪽 상세에는 업무 번호, 담당자, 업무 상태, 제출 버전·일시, 결과 설명과 반려 사유를 표시한다.
오른쪽은 **첨부 자료 / 제출 버전 이력** 탭으로 나눠 같은 공간을 사용한다.
첨부 파일명·버전·크기와 다운로드 버튼을 배치했다.
하단이 작아진 만큼 긴 내용과 표는 내부 스크롤로 확인한다.
표의 행 선택은 상세를 실제 조회하는 기능과 연결하지 않았다.

목록 상태 열과 제출 버전 기록은 **진행전 / 진행중 / 제출완료 / 승인완료 / 반려완료** 용어를 사용한다.
필터는 전체 상태와 위 5개 상태를 선택하도록 표시한다.
이전의 처리상태·진행상태 이중 표시와 `진행완료` 예시를 최신 로컬 결과물·이력에서 정리했다.
필터 선택은 고정 예시를 실제로 검색하거나 업무 상태를 바꾸지 않는다.

## 관련 화면의 역할

| 화면 | 화면 뼈대의 역할 |
|---|---|
| `ReviewsControl` | 결과물 목록, 고정 상세, 첨부·버전 탭, 제출 또는 판단 창 진입 |
| `SubmissionForm` | 결과 설명 입력, 첨부 예정 목록, 이전 제출본과 첨부 자료 표시 |
| `ReviewDecisionForm` | 제출 결과와 검토 의견·반려 사유 입력 위치, 승인·반려 버튼 표시 |
| `HistoryControl` | 생성·배정·수락·제출·승인·반려의 고정 이력 표시 |

`SubmissionForm`의 오른쪽 영역도 **첨부 예정 / 이전 제출물** 탭으로 구성했다.
작은 두 표를 위아래로 나눌 때 생기던 첨부 행 잘림을 줄이기 위한 배치다.
기본 생성자는 유지하고, 관리자 본인 제출 창은 역할을 받는 생성자로 해당 고정 예시를 표시한다.
`ReviewDecisionForm`은 승인·반려 표시를 나누되 기본 생성자와 기존 창 열기 경로를 유지한다.
승인·반려는 버튼 행동명이므로 그대로 사용하며, 기록 상태는 `승인완료`·`반려완료`로 표시한다.

관련 소스는 `RemoteWork.WinForms/Features/Results/`의 각 화면 `.cs`, `.Designer.cs`, `.resx`다.
관리자 범위 선택 `cmbResultView`의 세부 동작은 [관리자 본인 업무 기록](09_관리자_본인업무_수락과제출.md)을 참조한다.
업무 이력은 통합 상태에 맞추고, 별도의 진행률 완료 기록을 제거했다.
반려 후 재작업으로 돌아가는 시점을 화면 예시만으로 새 규칙처럼 확정하지 않았다.

## 검증 범위와 게시 구분

최신 로컬 QA에서 결과 목록 4행, 상태 필터, 제출 버전 상태와 제출·승인·반려 창 경로를 확인했다.
수치는 전체 [화면 뼈대 검증 기록](12_화면뼈대_검증기록.md)에서 구분한다.
제출·첨부·제거·다운로드·승인·반려의 실제 저장·전송·상태 변경은 구현하지 않았다.
범위 전환만 해당 고정 예시를 바꾸며, 업무 버튼은 준비 중 안내를 유지한다.
원격 alpha 코드 참조 `0d06c7108ef03f1638112a858a62f8c9fa11714c` 이후의 5개 상태·관리자 범위 변경은 로컬본에 있다.
이 문서의 LOG 게시를 최신 결과물 코드의 원격 배포 완료로 해석하지 않는다.
