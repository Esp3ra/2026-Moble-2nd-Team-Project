# 예시 데이터 일관성 수정

- 정리일: 2026-10-16
- 기록 순서: 같은 날 작성한 12번 검증 기록 이후의 후속 수정·검증
- 반영 커밋: `36dda613ac6194015e41da70038f6d420cec85fa`
- 게시 상태: `alpha`와 `0.0.2V`가 위 커밋을 가리키도록 게시 완료

## 수정 배경

README와 폼을 대조하는 과정에서 서로 다른 화면의 고정 예시 값이 맞지 않는 3건을 확인했다.
사용자에게 차이를 먼저 알린 뒤, 해당 예시 데이터만 정리했다.
이 기록은 위 커밋 전체 변경이 아니라 사전 안내한 3건과 관련된 4개 파일의 교정 범위를 다룬다.

## 변경 전과 후

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 검토 요청 마감일 | 직원 `TASK-003`·관리자 `TASK-A003` 목록은 2026-10-21, 검토 요청 창은 2026-10-22 | 검토 요청 창도 2026-10-21로 맞춤 |
| 직원 출퇴근·연차 본인 정보 | 메인 사원정보는 김직원·개발팀, 직원 기록 행과 연차 신청자는 이서연·기획팀 | 직원 기록 행과 신청자를 김직원·개발팀으로 맞춤 |
| 동일 결과물 담당자 | `WRK-2026-003`의 직원 목록은 김직원, 관리자 검토 목록은 박지은 | 관리자 검토 목록도 김직원으로 맞춤 |

직원 출퇴근·연차의 수정 대상은 본인 기록과 신청자다.
관리자 화면에서 조회하는 다른 직원의 신청 예시를 모두 본인 이름으로 바꾸지는 않았다.
검토 요청 날짜는 목록의 해당 업무와 연결해 확인했고, 서로 다른 업무의 마감일을 일괄 변경하지 않았다.

## 변경 범위

- 고정 문자열과 예시 행의 이름·부서·날짜를 바로잡았다.
- 서버 조회나 로그인 정보의 자동 바인딩 기능을 추가한 것은 아니다.
- 업무·결과물·연차 저장, 상태 변경, 승인·반려와 API·DB 연결은 추가하지 않았다.
- 업무 버튼은 계속 준비 중 안내를 표시하며 입력 내용이나 예시 기록을 저장하지 않는다.
- 화면 열기·닫기와 기존 관리자 범위 선택에 따른 고정 예시 전환은 유지한다.

## 후속 검증 결과

수정된 게시용 Release 빌드를 외부 UI 검증기로 실행했다.
기존 업무·결과물 범위 검증을 유지하고 이번 3건의 런타임 교차 검증을 추가했다.

| 검증 항목 | 이번 결과 |
|---|---:|
| 전체 검증 | 347개 통과 |
| 기본·최소 크기 화면 렌더 | 44개 |
| 모달 열기 경로 | 15개 |
| 준비 중 액션의 데이터 불변 | 21개 |

`qa-result.json`의 `crossChecks`에서 다음 실측값을 직접 확인했다.

| 교차 확인 | 실측 결과 |
|---|---|
| 직원 검토 요청 | `TASK-003` 목록 마감일 2026-10-21 = 열린 요청 창 2026-10-21 |
| 관리자 본인 검토 요청 | `TASK-A003` 목록 마감일 2026-10-21 = 열린 요청 창 2026-10-21 |
| 직원 출퇴근·연차 | 메인 김직원·개발팀 = 두 표의 모든 본인 행 = 연차 신청자 김직원·개발팀 |
| 결과물 담당자 | `WRK-2026-003` 직원 본인 목록 김직원 = 관리자 검토 목록 김직원 |

날짜 검증은 21일을 기대값으로 고정하지 않고, 열린 요청 창의 업무 ID로 목록 행을 찾아 비교했다.
검증 JSON과 화면 이미지는 별도 보관하며 이 문서에는 결과를 요약했다.
확인한 기본·최소 화면에서 새로운 범위 혼합이나 화면 잘림 결함은 발견하지 못했다.
이 결과는 화면 뼈대와 예시 일관성 검증이며 실제 서버 기능 완료를 뜻하지 않는다.
12번의 322개·40개 렌더·14경로·20액션 기록은 이전 검증 회차로 보존한다.
