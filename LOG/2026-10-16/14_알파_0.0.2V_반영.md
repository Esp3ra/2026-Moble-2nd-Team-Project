# alpha와 기존 0.0.2V에 최신 폼·계획서 반영

정리일: 2026-10-16

[변경 기록 목록으로](../../README.md) · [13. 예시 데이터 일관성 수정](13_예시데이터_일관성_수정.md)

이 문서는 최초 LOG 기록 01~12 이후에 수행한 **후속 코드 게시 완료 기록**이다.
01~12에서 최신 5개 상태·관리자 화면 수정을 로컬 작업본으로 구분했던 시점과 이번 게시 시점을 구분한다.
예시 데이터 차이는 수정 전에 사용자에게 알렸고, 정적 예시를 보정한 내용은 기록 13에 정리한다.

## 사용자가 확정한 반영 방식

- 작은 예시 차이를 수정한 뒤 최신 폼·계획서·README를 `alpha`와 기존 `0.0.2V`에 반영한다.
- 이번 수정은 새 버전 태그를 추가하는 대신 기존 `0.0.2V`를 최신 수정본으로 갱신한다.
- 초기 코드 배치 초안인 `0.0.1V`는 유지한다.
- 푸시할 때마다 README를 실제 폼·계획서·구현 범위·검증 결과에 맞춰 최신화한다.

`alpha`와 `0.0.2V`는 원격의 이전 태그 객체를 정확히 지정한 `force-with-lease`와 `atomic` 갱신으로 함께 게시했다.
동시 게시 뒤 브랜치 커밋과 태그를 해제한 커밋이 같은지 다시 확인했다.

## 반영한 화면과 문서

- 업무 상태를 **진행전 / 진행중 / 제출완료 / 승인완료 / 반려완료** 5개로 통일했다.
- 우선순위와 진행률, 진행·처리의 이중 상태 표시는 제거했다.
- 관리자의 **내 업무 / 관리 업무**, **내 결과물 / 결과물 검토**를 표준 ComboBox로 구분했다.
- 관리자도 본인 업무의 수락 버튼과 결과 제출·재제출 창에 접근할 수 있도록 배치했다.
- 관리자 본인 결과는 상위 검토자가 판단한다는 원칙을 예시에 표시하고, 본인 화면에는 자기 승인·반려 버튼을 두지 않았다.
- 표준 `.cs`, `.Designer.cs`, `.resx` 구조와 기본 생성자를 유지했다. 전체 구성은 Form 13개와 UserControl 6개다.
- 같은 업무의 검토 요청 마감일, 결과물 담당자, 직원 출퇴근·연차 신청자의 예시를 일치시켰다.
- `DOCX/2번_업무_상태_마감_구현계획.md`를 추가하고 확정 규칙·API/DB 제안·합의 필요 항목을 구분했다.
- README에 최신 버전, 관리자 화면 범위, 창 진입과 준비 중 처리 버튼의 차이, 검증 결과를 반영했다.
- 본인 업무·관리 업무·결과물 화면을 포함한 현재 미리보기를 함께 갱신했다.

상태의 실제 저장 코드, 상위 검토자 권한 매핑과 반려 후 재작업 복귀 시점 등은 구현계획의 합의 필요 항목을 따른다.
