# 도구상자에서 편집할 수 있는 폼 구조로 전환

기록일: 2026-10-16

이 문서는 도구상자 전환 기준과 최신 로컬 프로젝트의 파일 구조를 기록한다.
각 변경의 개발일을 추정해 나누지 않으며, 최신 코드의 원격 배포 완료를 뜻하지 않는다.

## 변경 배경

초기 17개 화면에도 `.cs`, `.Designer.cs`, `.resx` 파일이 있었지만 실제 배치는 `UiKit` 공통 생성 함수에 의존했다.
기능 화면은 생성자와 `BuildPreview()`에서 배치를 만들었고, 일부 Form은 `.Designer.cs` 안에서도 `UiKit.Dialog` 같은 함수를 호출했다.
`UiKit.Page`, `UiKit.Dialog`, `UiKit.Card`가 실행 중 컨트롤을 생성하는 구조였다.
따라서 파일이 세 종류라는 사실만으로 도구상자와 속성 창에서 화면 전체를 편집할 수 있는 구조는 아니었다.
초기 구조는 `0.0.1V`의 `RemoteWork.WinForms/Ui/UiKit.cs`와 결과 화면 코드에서 확인할 수 있다.

화면 배치를 표준 WinForms Designer 코드로 옮기고, 기능 담당자가 해당 화면을 직접 편집할 수 있도록 바꿨다.
이후 관리자 업무 요청 확인 창과 연차 판단 창을 추가해 현재 로컬 구성은 19개 화면이다.

## 현재 파일 구성

| 구분 | 수량 또는 역할 |
|---|---|
| 전체 화면 | Form 13개와 UserControl 6개, 총 19개 |
| `화면명.Designer.cs` | 표준 컨트롤 필드, 생성, 배치, 표의 열, 이름 있는 이벤트 연결 |
| `화면명.cs` | 생성자, 고정 예시 데이터, 역할·화면 범위 표시, 창 이동, 준비 중 안내 |
| `화면명.resx` | 해당 화면의 리소스 |

표준 `Panel`, `TableLayoutPanel`, `FlowLayoutPanel`, `Label`, `TextBox`, `ComboBox`, `DataGridView`, `Button` 등을 사용한다.
컨트롤 생성과 부모 연결은 각 `.Designer.cs`의 `InitializeComponent()`에 명시한다.
이 메서드에서 공통 화면 생성 함수, 반복문, 조건문으로 화면을 조립하지 않는다.
샘플 행을 채우는 `Rows.Add`와 역할별 표시 처리는 `.cs`에 둔다.
표의 열 정의는 `.Designer.cs`에 남겨 디자이너에서 수정할 수 있게 한다.
이벤트는 `Unavailable_Click`처럼 이름 있는 메서드로 연결한다.

모든 화면은 실제 매개변수 없는 기본 생성자를 유지한다.
역할·등록/수정·승인/반려 등의 추가 생성자는 기본 생성자와 함께 사용한다.
디자인 모드에서는 런타임 샘플 초기화를 건너뛰므로, 표의 예시 행이 비어 보일 수 있다.
역할별 버튼은 디자이너에서 함께 배치하고 실행 시 필요한 항목만 표시한다.

## 디자이너 사용 기준

1. `RemoteWork.sln`을 열고 화면 이름의 `.cs`에서 **디자이너 보기**를 선택한다.
2. 예를 들어 `RemoteWork.WinForms/Features/Tasks/TasksControl.cs`를 열어 업무 화면을 편집한다.
3. 도구상자로 컨트롤을 추가하고 속성 창에서 이름·문구·색상·배치를 바꾼다.
4. 패널 내부 배치는 `Dock`, `Anchor`, 행·열 크기와 여백으로 조정한다.
5. 새 이벤트의 처리 코드는 `.cs`에 작성하고, 배치 코드는 디자이너가 관리하게 둔다.

공통 메뉴에서 기능 화면을 넣는 위치는 `RemoteWork.WinForms/Shell/MainForm.cs`가 관리한다.
프로젝트의 파일 중첩·화면 종류 설정은 `RemoteWork.WinForms/RemoteWork.WinForms.csproj`에 있다.
고해상도 편집 기준을 위한 `ForceDesignerDPIUnaware`와 실행 배율 설정도 이 프로젝트 파일에서 관리한다.
새 화면은 `RemoteWork.WinForms/Features/Tasks/TaskRequestsForm`과 `RemoteWork.WinForms/Features/Attendance/LeaveDecisionForm`의 세 파일 구성을 따른다.

## 뼈대 범위와 기록 기준

메뉴·탭·고정 화면 범위 전환, 입력란 편집, 창 열기·닫기와 스크롤을 연결했다.
업무 처리 버튼은 `RemoteWork.WinForms/Ui/PreviewActions.cs`의 준비 중 안내만 표시한다.
인증, 서버 통신, DB 저장, 파일 전송과 실제 상태 변경을 구현한 기록은 아니다.
최신 상태 정의는 [업무 상태 5단계](08_업무상태_5단계_통일.md), 관리자 화면 범위는 [관리자 본인 업무](09_관리자_본인업무_수락과제출.md)에서 설명한다.
검증 횟수와 범위는 [검증 기록](12_화면뼈대_검증기록.md)을 따른다.
기록 기준 원격 alpha 코드 참조는 `0d06c7108ef03f1638112a858a62f8c9fa11714c`이며 3단계 표시 시점의 코드다.
그 뒤의 5개 상태·관리자 본인 범위 수정은 최신 로컬본의 변경으로 기록하며, 이 LOG 게시와 코드 배포를 구분한다.
