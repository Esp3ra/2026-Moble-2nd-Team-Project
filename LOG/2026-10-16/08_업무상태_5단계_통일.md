# 업무 상태 5단계 통일

기록일: 2026-10-16

이 문서는 도구상자·디자이너 방식 전환 이후 로컬에 반영한 상태 표시 변경을 기록한다.
기록일은 문서를 정리한 날짜이며 개별 수정의 실행 시점을 추정한 날짜가 아니다.
이번 LOG 게시는 변경 기록만 대상으로 하며 코드나 태그를 갱신하지 않는다.
기록 시점의 원격 `alpha`와 `0.0.2V`는 `0d06c7108`의 종전 진행 3단계 코드 기준이다.

## 변경 이유

진행 상태와 처리 상태를 따로 표시하면 작업 완료, 결과 제출, 관리자 승인을 혼동할 수 있었다.
사용자 결정에 따라 업무 전체에서 사용할 상태를 하나의 5단계 기준으로 정리했다.
상태 이름의 확정과 실제 서버 상태 전환 구현은 구분한다.

## 변경 전과 후

| 구분 | 변경 전 | 로컬 변경 후 |
|---|---|---|
| 상태 구조 | 진행전·진행중·진행완료와 별도 처리 상태 | 단일 업무 상태 5개 |
| 목록·상세 | 진행과 처리 상태를 각각 표시 | 업무 상태 하나로 표시 |
| 업무 상태 필터 | 5개 통합 상태의 선택 항목 없음 | 전체와 5개 업무 상태 선택 |
| 완료 의미 | 진행완료와 승인 여부의 구분 필요 | 승인완료일 때만 최종 완료 |

| 업무 상태 | 확정된 의미 |
|---|---|
| 진행전 | 배정됐으나 담당자가 아직 수락하지 않음 |
| 진행중 | 담당자가 업무를 수락해 수행함 |
| 제출완료 | 정식 제출 후 검토자의 판단을 기다림 |
| 승인완료 | 검토자가 승인했으며 업무가 최종 완료됨 |
| 반려완료 | 반려 판단이 끝났으며 수정·재제출이 필요함 |

## 확정된 기본 전환

- 업무를 배정하면 진행전으로 시작한다.
- 직원 또는 관리자 담당자가 수락하면 진행중이 된다.
- 결과를 정식 제출·재제출하면 제출완료가 된다.
- 권한 있는 검토자가 승인하면 승인완료, 반려하면 반려완료가 된다.
- 반려완료는 반려 판단의 완료이며 업무의 최종 완료를 뜻하지 않는다.

## 현재 로컬 반영

- 업무 목록·상세·상태 필터와 결과물·이력의 상태 표시를 같은 용어로 정리했다.
- 업무 목록의 상태 열은 하나이며 우선순위와 숫자 진행률은 사용하지 않는다.
- 상태 필터는 표준 ComboBox의 선택 항목만 제공한다. 실제 필터링은 실행하지 않는다.
- 목록의 상태는 고정 샘플이다. 수락·제출·판단 버튼으로 상태를 바꾸지 않는다.
- 계획서의 업무 상태 논리안도 단일 `task_status`로 맞췄다.

## 합의 필요

- 1번·3번: 5개 상태의 저장 코드, DB 기본값과 API·DB 연결 규격.
- 1번·3번: 반려완료 후 재작업을 위해 진행중으로 복귀시키는 시점.
- 1번·3번: 제출 기록·검토 결과와 업무 상태가 함께 일치하도록 연결하는 방식.
- 기본 5개 상태와 수락·제출·승인·반려에 따른 위 전환 자체는 확정 사항이다.

## 확인 범위와 한계

표시 용어와 필터 항목을 정리한 화면 뼈대 변경이다.
실제 인증, 업무 저장, 상태 전환, 서버 권한 검사는 아직 연결하지 않았다.
요청의 확인 대기 같은 처리 상태는 요청 자체의 상태이며 두 번째 업무 상태가 아니다.

## 확인한 로컬 기준

- `RemoteWork.WinForms/Features/Tasks/TasksControl.cs` 및 `.Designer.cs`
- `RemoteWork.WinForms/Features/Results`의 목록·이력 화면
- `DOCX/2번_업무_상태_마감_구현계획.md`의 상태 의미·단일 상태 논리안
