# 업무의 협업 요청과 관리자 요청 확인 화면

정리일: 2026-10-16

업무에 연결된 요청을 업무 화면에서 찾을 수 있도록 정리했다. 협업 요청은 업무로 옮기고, 관리자에게 마감 연장·검토 요청을 확인할 별도 창을 추가했다.

## 변경 전과 후

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 협업 요청 진입 | 채팅·협업 화면에서 접근 | 직원·관리자 업무 화면에서 접근 |
| 채팅 화면 | 협업 요청 진입과 대화 화면이 함께 있음 | 대화 중심으로 분리 |
| 관리자 요청 확인 | 업무 관련 요청을 모아 보는 창이 없음 | 업무 화면의 요청 확인 버튼에서 별도 창 열기 |
| 요청 구분 | 개별 신청 창 중심 | 마감 연장·검토 요청을 한 목록에서 구분 |

## 반영한 화면

- 업무의 협업 요청 버튼에서 기존 협업 요청 Form을 연다. 협업·채팅 데이터의 소유 범위는 4번 담당을 유지한다.
- 관리자 요청 확인 창은 요청 유형·업무·요청자·요청일·요청 상태를 표시한다.
- 아래에 마감 연장 사유·희망 마감일과 검토 요청 내용을 나누어 배치한다.
- 초기 검토 요청 예시는 진행 중인 작업 방향을 확인하는 내용이었다. 최신 로컬 수정본은 **제출완료된 결과의 검토 요청** 예시로 바꿨다.
- 최신 로컬 수정본에서 관리자는 **관리 업무**를 선택해 요청 확인 창에 들어간다. 본인 업무 요청 경로는 [관리자 본인 업무 기록](09_관리자_본인업무_수락과제출.md)에 정리했다.

요청의 **확인 대기**는 요청 자체의 상태다. 업무 상태 5개와 같은 값으로 취급하지 않는다. 결과 제출 후 관리자 검토 연결 원칙은 [필수 검토 기록](10_결과제출_필수검토_자동제출제외.md)을 따른다.

## 동작 범위와 합의 필요

현재는 창 열기·닫기, 입력 항목과 고정 요청 예시만 제공한다. 목록 선택에 따른 상세 조회, 요청 전송·확인 기록·마감 변경·채팅 연결은 구현하지 않았다.

정식 결과 제출은 반드시 관리자 검토 대상으로 연결해야 한다. 이를 요청 기록과 결과물 검토 목록에 연결하는 방식, 연장 신청 조건과 반영 규칙은 관련 담당과 **합의 필요**다. 협업 요청의 저장·채팅 연동은 4번과 맞춘다.

관리자 요청 창 추가는 `alpha`의 `0.0.2V`에 포함된 화면 변경이다. 제출완료 예시와 관리자 화면 구분은 이후의 로컬 수정본에 반영한 내용으로, 이 LOG 게시가 해당 소스의 추가 배포를 뜻하지 않는다.
