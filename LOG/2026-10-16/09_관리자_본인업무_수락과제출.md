# 관리자 본인 업무 수락과 결과 제출 화면

기록일: 2026-10-16

도구상자·디자이너 방식 전환 이후 로컬 화면에 추가한 관리자 본인 업무 구분을 기록한다.
기록일로 개별 코드 수정일을 추정하지 않는다.
이번 LOG 게시는 문서만 대상으로 하며 원격 `alpha` 코드와 `0.0.2V` 태그는 갱신하지 않는다.
기록 시점의 원격 코드 기준은 `0d06c7108`이며 아래 화면 구성은 아직 포함되지 않은 로컬 반영분이다.

## 변경 이유

관리자에게도 직접 배정받아 수행할 업무가 있으므로 관리 기능과 본인 수행 기능을 구분해야 했다.
관리자 역할이라는 이유로 본인 업무의 수락·제출 화면이 빠지지 않도록 구성했다.
동시에 본인 결과물의 승인·반려는 상위 검토자가 맡는 기준을 정리했다.

## 변경 전과 후

| 영역 | 변경 전 | 로컬 변경 후 |
|---|---|---|
| 관리자 업무 | 등록·수정·취소 등 관리 기능 중심 | 내 업무 / 관리 업무 선택 |
| 관리자 결과물 | 다른 담당자의 결과물 검토 중심 | 내 결과물 / 결과물 검토 선택 |
| 직원 | 본인 업무·결과물 화면 | 본인 화면 유지, 관리자 범위 선택 숨김 |
| 관리자 본인 결과물 판단 | 별도 권한 연결 기준 필요 | 상위 검토자 판단, 자기 판단 금지 원칙 명시 |

## 현재 로컬 반영

표준 WinForms ComboBox를 Designer에 배치하고 이름 있는 이벤트 처리기로 연결했다.
관리자 화면은 처음 열 때 본인 범위가 기본 선택된다.
선택을 바꾸면 미리 준비한 샘플 목록·상세와 버튼 표시만 전환한다.

| 화면과 선택 | 표시하는 버튼·내용 |
|---|---|
| 업무: 내 업무 | 본인 고정 업무, 수락·검토 요청·마감 연장 |
| 업무: 관리 업무 | 관리 대상 고정 업무, 등록·수정·취소·요청 확인 |
| 결과물: 내 결과물 | 본인 고정 결과물·버전, 결과 제출 창 열기 |
| 결과물: 결과물 검토 | 검토 대상 고정 결과물, 승인·반려 창 열기 |

- 업무 구분 컨트롤: `cmbTaskScope`, 선택 항목은 내 업무 / 관리 업무.
- 결과물 구분 컨트롤: `cmbResultView`, 선택 항목은 내 결과물 / 결과물 검토.
- 관리자의 본인 샘플 담당자는 목록·상세·제출 창에서 맞춰 표시한다.
- 관리자 본인 결과물의 상세에는 상위 검토자 검토 대상임을 표시한다.
- 직원에게는 범위 선택을 숨기고 본인 업무·결과물만 표시한다.
- 메인 결과물 메뉴 이름은 직원·관리자 모두 결과물로 통일한다.
- 협업 요청은 업무 화면에서 기존대로 열 수 있다.

## 확정된 판단 원칙

관리자도 본인에게 배정된 업무를 수락하고 결과를 제출·재제출할 수 있다.
관리자 본인의 정식 제출본·재제출본은 상위 검토자가 승인 또는 반려해야 한다.
관리자가 본인 제출본을 스스로 승인하거나 반려하는 것은 허용하지 않는다.
화면의 내 결과물 범위에서는 승인·반려 버튼을 표시하지 않는다.

## 합의 필요

- 1번·3번: 상위 검토자를 어떤 계정과 권한으로 매핑할지.
- 1번·3번: 본인·관리 범위와 결과물 검토 범위를 서버에서 검사하는 규격.
- 1번·3번: 제출자와 판단자의 동일인 여부를 제출 버전 기준으로 확인하는 연결 방식.
- 1번·3번: 검토자 조회와 제출·판단 API의 공통 사용자 식별자.

## 동작 범위와 확인 기준

범위 선택은 고정 데이터의 화면 전환이며 실제 업무 조회나 권한 검사가 아니다.
수락·등록·제출·승인·반려 같은 업무 액션은 준비 중 안내를 표시한다.
자기 판단 금지는 확정된 업무 규칙이며 실제 서버 차단 코드는 아직 구현하지 않았다.
기본 선택, 전환 후 버튼 구분, 본인 샘플 담당자 일치와 원복을 화면 확인 기준으로 삼는다.

## 확인한 로컬 기준

- `RemoteWork.WinForms/Features/Tasks/TasksControl.cs` 및 `.Designer.cs`
- `RemoteWork.WinForms/Features/Results/ReviewsControl.cs` 및 `.Designer.cs`
- 역할에 따라 열리는 검토·연장·결과 제출 창과 로컬 구현계획서

위 경로는 로컬 근거이며 이번 LOG 브랜치가 해당 소스를 제공한다는 뜻은 아니다.
