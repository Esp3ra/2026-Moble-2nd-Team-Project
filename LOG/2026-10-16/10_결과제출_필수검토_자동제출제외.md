# 결과 제출 필수 검토와 자동 제출 제외

기록일: 2026-10-16

이 문서는 사용자 결정으로 확정된 제출·검토 원칙과 제외 범위를 기록한다.
개별 결정의 과거 날짜를 추정하지 않고 기록일만 표시한다.
이번 LOG 게시는 로컬 결정·화면·계획의 기록이며 코드나 태그를 갱신하지 않는다.
기록 시점의 원격 `alpha`와 `0.0.2V`는 `0d06c7108`의 종전 코드이며 이 문서가 최신 기능 구현을 뜻하지 않는다.

## 변경 이유

초기 구상에는 마감 시 자동 검토 요청과 자동 결과 제출이 함께 있어 의미를 나눌 필요가 있었다.
직접 결과를 제출했는데 별도 검토 요청을 누르지 않아 검토에서 빠지는 일도 없어야 한다.
사용자는 모든 제출본의 관리자 판단을 필수로 정하고 자동 제출은 제외했다.

## 변경 전과 후

| 항목 | 이전 구상·미정 사항 | 확정한 기준 |
|---|---|---|
| 정식 제출 | 제출과 별도 검토 요청의 연결 방식 불명확 | 모든 제출본을 반드시 관리자 판단 대상으로 연결 |
| 재제출 | 다시 검토할지 명시 필요 | 모든 재제출본도 다시 승인·반려 |
| 최종 완료 | 작업 완료·제출 완료와 혼동 가능 | 관리자 승인에 따른 승인완료일 때만 최종 완료 |
| 마감 자동 제출 | 마감이면 자동 제출한다는 초기 구상 포함 | 기능 범위에서 제외 |
| 자동 검토 요청 | 자동 제출과 혼용 가능 | 별도 기능이며 도입·조건은 합의 필요 |

## 확정된 기본 흐름

1. 관리자가 업무를 배정하면 담당자는 진행전 상태의 업무를 확인한다.
2. 직원 또는 관리자 담당자가 수락하면 진행중으로 구분한다.
3. 담당자가 결과를 정식 제출하면 제출완료로 구분하고 검토 판단을 기다린다.
4. 권한 있는 관리자가 승인하면 승인완료, 반려하면 반려완료로 구분한다.
5. 반려 후 수정한 결과를 재제출해도 다시 관리자 승인·반려를 거친다.

반려완료는 반려 판단이 끝났다는 뜻이며 최종 업무 완료가 아니다.
관리자 본인의 정식 제출·재제출은 상위 검토자가 판단하며 자기 승인·반려는 허용하지 않는다.
별도 검토 요청 버튼을 누르지 않아도 정식 제출본은 관리자 검토에 포함돼야 한다.

## 자동 제출 제외의 의미

- 마감이 지났다는 이유만으로 결과물을 제출한 것으로 만들지 않는다.
- 마감 경과만으로 제출 기록·제출 시각·제출 버전을 생성하지 않는다.
- 마감 경과만으로 업무 상태를 제출완료·승인완료로 바꾸지 않는다.
- 실제 제출은 담당자의 직접 제출·재제출 행동으로 처리하도록 설계한다.
- 자동 검토 요청은 검토·확인 요청을 만드는 별도 개념이며 결과 제출을 대신하지 않는다.

## 현재 로컬 반영

계획서와 README에 필수 검토·승인 후 최종 완료·자동 제출 제외를 반영했다.
업무·결과물 화면은 5개 업무 상태의 고정 샘플을 표시한다.
검토 요청 창은 제출완료된 결과를 검토하는 예시를 표시한다.
요청 자체의 확인 대기 상태를 결과물 승인이나 두 번째 업무 상태로 해석하지 않는다.
실제 제출 기록 생성, 검토 대상 연결, 버전 보존과 승인·반려 처리는 아직 구현하지 않았다.

## 합의 필요

- 1번·3번: 제출·재제출이 필수 검토 대상으로 연결되는 API·DB 규격.
- 1번·3번: 제출 버전과 판단 결과 연결, 상위 검토자 권한과 동시 판단 처리.
- 1번·3번: 반려완료 후 재작업을 위해 진행중으로 복귀시키는 시점.
- 3번: 자동 검토 요청을 도입할지, 도입한다면 어떤 조건·회차로 만들지.
- 2번·3번: 마감 후 직접 제출을 허용할지와 연장 신청·승인 조건.
- 자동 제출 제외와 모든 정식 제출·재제출의 필수 판단 원칙은 합의 대상이 아니라 확정 사항이다.

## 확인한 로컬 기준

- `DOCX/2번_업무_상태_마감_구현계획.md`의 제출·검토 원칙과 검증 항목
- 로컬 `README.md`의 업무 상태와 동작 범위
- 결과 제출·검토 창은 화면 뼈대이며 버튼은 실제 처리를 수행하지 않음

위 경로는 로컬 검토 근거다. 원격 태그가 이 결정에 따른 최신 코드를 포함한다는 링크는 제공하지 않는다.
