# 업무 조회 연결 준비 검증

Windows와 .NET 8 SDK에서 실행합니다.

```powershell
dotnet run --project .\Tests\TaskQueries.Tests\TaskQueries.Tests.csproj -c Release
```

선택 인자로 캡처 저장 폴더를 전달하면 기본 실행과 테스트 대역 화면을 PNG로 저장합니다. 이미지·빌드 출력은 Git에 추가하지 않습니다.

검증 범위는 명시적으로 주입한 조회 테스트 대역과 실제 WinForms 컨트롤입니다. 실행기는 실제 `Application.Run` 메시지 루프에서 동작하며 UI 스레드 교차 접근 검사를 활성화합니다. 기본 TasksControl·미리보기 생성자의 미연결 상태, 목록·상세, 전체와 5개 상태 필터, 내 업무·관리 업무의 조회 집합, 로딩·빈 목록, 오류별 표시·재시도, 이전 비동기 응답 무시, 잘못된 상세 ID 거부, 화면 닫기 중 취소를 확인합니다. 테스트 데이터의 ID는 불투명 문자열이며 서버 PK나 인증 사용자 ID가 아닙니다. 실제 로그인 MainForm의 HTTP 주입은 별도 [HTTP 검증](../TaskQueries.Http.Tests/README.md)에서 확인합니다.

추가 회귀는 동일 조건 재조회 시 선택 유지·응답 순서 변경·선택 업무 삭제/빈 목록·조건 변경, 상세 실패 종류별 선택 업무만 재시도·호출 횟수·성공 후 전체 조회 복귀, F5 전체 조회, 서비스 취소의 데이터 제거·복구·늦은 취소 무시를 확인합니다.

목록과 이후 상세의 요약이 달라지는 경우도 명시적 조회 대역과 실제 WinForms로 검사합니다. 제목·담당자 표시명·상태·시작일·마감일 변경 안내, 목록 스냅샷/필터 보존, 최신 상세의 입력 준비 전달과 목록 새로고침 후 선택·안내 복구를 확인합니다. 서버 동시 쓰기나 DB 경합을 재현한 테스트는 아닙니다.

입력 준비 회귀는 빈 등록 폼·필수 제목/날짜·200 Unicode 문자 경계·날짜 역전, 실제 선택 상세의 수정 입력, Picker 범위 밖 날짜 보존, 연장 희망일/사유 형식 검사·원본 마감일 보존, 5개 상태의 읽기 전용 수락 대상을 확인합니다. 실제 버튼으로 모달을 열어 선택한 업무가 전달되는지 검사하고, 상세 로딩/실패·늦은 응답·전체 재조회·빈 목록에서 이전 준비 문맥과 관련 버튼이 초기화되는지도 확인합니다. 서버 저장/접수·수락 상태 변경·파일·제출/검토 기능은 검사하지 않습니다. 입력 확인 성공을 실제 업무 처리 성공으로 표시하지 않습니다.

입력 확인 성공 시 불변 CheckedInput의 원본 ID·제목/내용·날짜/사유가 정확히 보관되는지도 검사합니다. 등록의 TaskId는 null이며 임의 ID를 만들지 않습니다. 확인 전·실패 후 null, 값 변경·날짜 체크 해제 시 무효화, 이전 record의 불변성, 프로그램으로 날짜 체크를 바꿔 이벤트가 발생하지 않는 경우의 읽기 시점 대조를 포함합니다. 이는 로컬 입력값이며 쓰기 API 계약이 아닙니다.

실제 인증·HTTP·서버 권한·DB·두 PC 연동은 실행하지 않습니다. 내 업무·관리 업무의 테스트 집합을 구분한 결과는 실제 서버의 조회 권한 검사를 검증한 것이 아닙니다. 서버에서는 인증된 사용자에 대해 목록과 상세 직접 접근 권한을 각각 검사해야 합니다.

공통 규약 확인과 남은 질문은 [조회 연결 경계](../../RemoteWork.WinForms/Features/Tasks/Queries/README.md)를 따릅니다.
