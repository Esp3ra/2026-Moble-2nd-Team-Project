# 결과 제출 폼 입력·상태 표시 검사

```powershell
dotnet run --project Tests/SubmissionForm.Ui.Tests -c Release
```

선택적으로 마지막 인수에 외부 캡처 폴더를 지정하면 최소 크기 오류 화면과 150% `Control.Scale` 화면 PNG를 저장한다.

실제 WinForms 메시지 루프와 텍스트 컨트롤을 사용한다. `.Text` 속성에 값을 대입하는 대신 Windows EDIT 컨트롤에 `WM_CHAR`를 전달해 한글·줄바꿈의 입력 허용과 읽기 전용 상태의 입력 차단을 확인한다. 물리 키보드나 IME, 다른 모니터의 실제 DPI 전환을 검증한 것은 아니다.

HTTP는 명시적인 대역이며 제품 서버·DB·계정·파일을 변경하지 않는다. 현재 43개 검사는 다음을 포함한다.

- 검토자·마감·연장 대기·권한·서버·버전 오류가 탭 전환 없이 보이는지 확인.
- 현재 본인 배정을 확인한 뒤 업무와 담당자를 표시하고, 제출 준비가 완료돼야 설명 입력을 허용.
- GET 재확인 실패 시 입력 설명은 유지하되 과거 준비 문맥을 무효화하며, 성공 후 입력을 다시 허용.
- 조회 중 및 로그인 변경 시 잠금, 불명확한 기존 제출 요청이 있으면 재조회 차단 및 결과 확인 흐름 유지.
- 최소 창과 150% 배치 확대에서 상태·재확인·닫기 버튼 영역 확인.

실제 서버 저장은 `Tests/TaskResults.Integration.Tests`의 격리 MySQL·HTTP 검사와 별도로 수행한다.
