# 일반수정 첨부 선택·요청 상태 검사

```powershell
dotnet run --project Tests/TaskManagementAttachments.Tests/TaskManagementAttachments.Tests.csproj -c Release
```

2026-10-22 실행: **13개 시나리오, 120개 검사 통과**.

제품 `ApiClient`, `TaskManagementSessionStore`, 일반수정 워크플로, 첨부 조회·업로드·DELETE·W1 HTTP 구현을 그대로 사용합니다. HTTP 응답과 응답 지연·유실은 명시적인 메모리 대역이며 파일은 검사 소유 임시 폴더의 합성 파일입니다. 실제 서버/DB/계정으로 실행한 결과가 아닙니다.

- 기존 첨부 미변경은 `attachment_ids` 생략, 전체 제외는 `[]`이며 기존 파일에 DELETE를 보내지 않습니다.
- 원래 업무·행 버전·배정 버전과 최종 파일 ID 순서를 요청 키 발급 전에 검사합니다. 다른 버전의 조회가 변경한 선택을 덮어쓰지 못하며 명시적인 로컬 초기화가 필요합니다.
- 기존 파일과 새 파일 합계는 10개 이하입니다. 새 파일은 명시 업로드 완료 전에는 변경 요청을 만들 수 없습니다. 원래 파일 바이트와 업무 대상은 고정됩니다.
- 같은 로그인·업무에서 창을 다시 열면 선택을 보존합니다. 재배정·관리자 변경에는 첨부 선택을 연결하지 않습니다.
- 목록 조회·업로드 중에는 변경 키 발급과 선택 변경이 차단됩니다. 변경 결과 불명·결과 조회·동일 요청 재전송 동안에는 원래 최종 목록을 고정합니다.
- 결과가 불명인 변경은 `not_recorded` 확인 후 같은 본문·키로만 재전송합니다. 성공 확인·세션 종료·화면 정리는 자동 DELETE를 보내지 않습니다.
- 확정된 첨부 사용 불가 오류는 선택을 유지한 편집 상태로 돌아갑니다. 401/403은 오래된 파일 정보를 정리하고, 권한 차단 후 같은 로그인에서 창을 다시 열어도 우회하지 못합니다.
- 이전 창이 취소한 목록 조회에 전송 대역이 취소를 무시하고 늦은 403을 반환해도 현재 세션·워크플로·변경한 파일 목록을 폐기하지 않습니다. 같은 로그인에서 다시 연 창은 그 목록을 그대로 저장할 수 있습니다. 취소하지 않은 현재 조회의 403 차단과 별도로 검사합니다.
- 로그아웃 뒤 늦은 업로드 시작 응답은 파일 목록을 복원하거나 청크 전송을 이어가지 않습니다. 새 임시 파일에 대해서만 명시 DELETE를 보냅니다.

실제 WinForms 화면 조작은 `../TaskManagementAttachmentUi.Tests`, 일반수정 서버 통합은 `../TaskManagementAttachments.Http.Tests`와 별도입니다. 생성 업로드 회귀는 `../TaskCreationUploads.Tests`의 20개 시나리오·440개 검사로 확인했습니다. 공유 서버의 운영 설정이나 팀원 실계정 검증을 대신하지 않습니다.
