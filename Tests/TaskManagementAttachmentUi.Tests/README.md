실제 STA WinForms 컨트롤을 화면 밖에서 조작하며 HTTP·파일 대화상자·업무 조회는 명시적 시험 대역입니다. `ApiClient`와 `TaskManagementSessionStore`의 실제 캡처 세션, 업무 대상에 고정된 업로드·최종 요청·W1 직렬화는 제품 소스를 그대로 사용합니다. 임시 합성 파일만 만들며 실제 API 서버/DB·실계정·공유 폴더에는 접근하지 않습니다.

2026-10-22 직접 실행 **149검사 통과**.

검사 범위:

- 기존 첨부는 업로드/DELETE 대상이 아니며 확인한 ‘업무에서 제외’는 로컬 최종 목록만 바꿉니다. 빈 목록을 본문 확인과 별도 실행을 거쳐 명시 `attachment_ids: []`로 전송합니다.
- 새 파일은 명시 선택→업로드를 거치고 원래 task_id와 기존 참조를 유지합니다. 창 닫기·재열기에서 선택이 보존되며 자동 삭제하지 않습니다.
- 임시 삭제 확인 중 선택 행이 바뀌어도 처음 확인한 파일 ID만 사용합니다.
- 첨부 선택 변경은 확인된 업무 요청을 무효화합니다. 응답 불명 창 재진입은 원문·파일 IDs를 읽기 전용으로 복원하고, 결과 조회 뒤 같은 본문/키만 재전송합니다. 결과 불명/재시도 허용 중 첨부 변경은 잠깁니다.
- 첨부 사용 불가/변경 없음으로 확정 실패한 뒤 사용자가 다시 고친 제목·내용은 후속 첨부 이벤트로 이전 요청 본문에 덮어쓰지 않습니다.
- context→파일→context 버전 경합은 원본 첨부에 새 버전을 붙이지 못합니다. 제공부503이면 빈 목록으로 간주하지 않고 첨부 생략을 통한 본문 수정만 가능합니다.401/403은 오래된 업무/파일 선택과 변경 버튼을 폐기합니다.
- 이전 조회 generation 또는 닫힌 폼에서 늦게 도착한 context403은 최신 조회·다시 열린 폼의 공유 workflow, 첨부 선택과 새 입력을 차단하지 않습니다. 취소 뒤에도 응답하는 명시 context 대역으로 확인하며, 현재 조회의 직접403 차단은 유지합니다. 공통 API의401 인증 폐기 규칙은 변경하지 않습니다.
- 다른 버전으로 재조회하거나 사용자가 같은 버전의 최신 조회를 누르면, 변경한 첨부 선택 초기화를 명시 확인합니다. 취소는 유지하고 동의해도 서버 DELETE를 보내지 않습니다.
- 처리 중 닫기/중복 동작 차단, 세션 폐기 뒤 늦은 삭제 응답 무효화를 확인합니다. 최소 크기에서 실제 폼 안의 버튼 경계와 파일 행, 업무 수정 입력 4개에 대한 스크롤 접근과 입력 행 사이 겹침 없음을 검사합니다.

이미지는 실제 컨트롤의 `DrawToBitmap` 결과이며 사람의 수동 조작 또는 실제 공유 서버 저장 성공 증거가 아닙니다. 최소 크기에서 스크롤 영역 밖 자식 컨트롤도 그려지는 `DrawToBitmap` 제한이 있으므로, 해당 이미지만으로 실제 화면의 잘림 처리를 검증했다고 판단하지 않습니다. 입력 접근성은 실제 컨트롤의 스크롤·좌표 검사로 확인합니다. 별도 HTTP/MySQL 검증은 최신 LOG/2번 구현검증 기록과 구분해 읽습니다.
