# 업무 등록 첨부 선택·명시 삭제 화면 검증

실제 WinForms와 공통 `ApiClient`를 사용하고 HTTP 응답만 명시 대역으로 제어합니다. 서버·DB·운영 파일 저장소·실계정은 사용하지 않습니다. 파일/확인 대화상자의 결과는 테스트 전용 폼에서 제어하고 실제 버튼 이벤트·선택 모델·등록 workflow를 통과합니다.

```powershell
dotnet run --project Tests/TaskCreationAttachmentUi.Tests/TaskCreationAttachmentUi.Tests.csproj -c Release
```

- 파일 선택은 로컬 준비만 수행, 업로드 완료만 등록 ID에 포함.
- 기본/디자인 폼의 동작 차단, 작은 창의 버튼 줄바꿈·파일 목록, 창 재진입의 같은 선택 유지.
- 선택만 해제·삭제 확인 거절은 DELETE 0회. 확인 중 선택 변경에도 최초 파일만 삭제.
- 삭제 응답 유실 뒤 같은 ID 재확인, 불명 파일 등록 차단, 확정404 정리.
- 만료 파일의 정확한 `409 ATTACHMENT_UNAVAILABLE` 삭제 거절 뒤 경고를 확인한 로컬 선택 해제. 서버 삭제 성공으로 표시하지 않음.
- 등록 응답 불명 동안 파일 변경/삭제 차단, 재진입 원문 유지, 성공 receipt 확인 뒤 자동 DELETE 없음.
- 결과 조회의 `not_recorded`로 재시도가 허용되거나 키 재사용으로 수동 확인 상태가 되어도 파일 선택·삭제·해제 차단 유지.
- 전송 중 중복/창 닫기 차단, 세션 변경 후 파일명 제거·늦은 응답 차단.
- 파일 작업 진행 중 등록 요청 0회, 세션 변경 뒤 늦은 삭제 응답으로 목록 복원·재시도 없음.

2026-10-22 실행 결과: **9개 시나리오, 95개 검사 통과**. 실제 STA WinForms 메시지 루프에서 교차 스레드 접근 검사를 켜고 실행했습니다. 기본 크기와 최소 크기 이미지는 명령 뒤 출력 폴더를 인수로 지정하면 생성됩니다.

실제 HTTP/MySQL DELETE는 `TaskCreationUploads.Tests/run_mysql_check.py`의 별도 검증이며 이 UI 대역 결과와 합산하지 않습니다. 수동 사용성, 실제 OS 파일 선택창/확인창 조작, 공유 서버/두PC와 일반수정 첨부·웹 첨부는 이 실행 범위가 아닙니다.
