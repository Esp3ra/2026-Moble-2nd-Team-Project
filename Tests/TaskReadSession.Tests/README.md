# 2번의 접속 고정 읽기 검사

```powershell
dotnet run --project Tests/TaskReadSession.Tests -c Release
```

실제 `ApiClient`와 `HttpTaskQueryService.CaptureReadSession()`을 사용하되, HTTP는 **명시적 인메모리 handler 대역**입니다. 실제 서버·DB·4번 알림/협업 기능을 검증하지 않습니다.

- 로그인한 접속만 명시적으로 capture하며 로그아웃·401·재로그인·서버 변경 뒤 옛 reader를 재사용하지 않습니다. source 설명은 capture 당시 값입니다.
- 기존 GET 경로·전체/5상태·취소 포함·날짜·상세 파싱을 재사용하고, 실패/취소를 빈 성공으로 바꾸지 않습니다.
- 호출자 취소, 접속 취소와 늦게 도착한 응답/DTO continuation을 검사합니다. shared client의 소유권과 서버의 권한 판단은 바꾸지 않습니다.
- 명시 업무 대역도 전체/5상태·본인/관리 범위에서 기본 취소 제외와 명시 포함을 지키는지 검사합니다. 이 로컬 필터는 서버 권한 검사가 아닙니다.

reader는 타이머·알림 수신 대상·시각·저장·자동 요청·쓰기 준비를 제공하지 않습니다. 특정 scope의 관계 확인에는 성공한 해당 scope 전체 목록을 사용해야 하며 상세 GET은 본인/지정 관리자 합집합 접근입니다. 응답 후 변경 경합, 현재 버전/배정 관계·서버 시각, 영속 중복키·여러 PC 동작은 이 검사/계약이 보장하지 않습니다.

소비자는 성공뿐 아니라 오류를 화면에 적용할 때도 현재 접속/화면 수명을 확인해야 합니다. 이미 완료된 옛403·503 오류가 새 로그인 뒤 전달될 수 있으며, 마지막 검사와 실제 UI 표시 사이의 경합을 이 facade만으로 해결하지 않습니다.
