상태: **실행 환경 확인 요청 / 회신 대기**. 새 정책 합의·서버 연결 성공·제품 기능 완료 보고가 아닙니다.

## 요청 목적과 현재 상태

직원·관리자 **04 결과물 → 내 결과물**에서 실제 업무 목록과 선택한 업무 상세를 확인하려고 합니다. 관리자 **04 결과물 → 결과물 검토**의 지정 관리 업무 조회도 확인하되, 이를 실제 검토자 권한이나 검토 대상 제출물 조회 완료로 해석하지 않습니다.

연결 구조는 다음과 같습니다.

```text
ReviewsControl → 기존 공통 로그인·ApiClient → 2번 업무 조회 API → 서버 MySQL
```

- 사용자(3번)가 새로 받은 alpha 프로젝트에 적용한 뒤 코드 오류가 없다고 확인했습니다. 이는 사용자 확인이며 이번 문서 작업에서 일반 빌드나 실서버 검증을 새로 실행한 결과가 아닙니다.
- 조회 연결 제안은 alpha `a4424dc5b5baeebb7ae7f79957bb2bce2d3729b0` 기준으로 준비했습니다. 실제 코드 SHA는 아래 확인 기준을 따릅니다.
- 3번이 사용할 서버 접속 주소·로그인 계정·업무 조회 환경을 아직 전달받지 못해 로그인 후 실제 조회를 확인하지 못했습니다. 공유 서버가 존재하지 않는다고 단정하는 것은 아닙니다.
- 이번 요청으로 제품 코드나 DB·공유 설정을 변경하지 않습니다. 3번의 로컬 조회 연결 코드는 이번에 alpha에 게시하지 않습니다.
- 제출·검토·첨부·제출 이력의 실제 서버 기능은 별도 3번 구현 대상입니다. 1번이 DB를 준비하면 자동으로 완성되는 기능으로 보지 않습니다.

## 1번 담당자에게 — 서버 접속과 로그인 환경

기존 공통 로그인·통신 코드는 제공된 회신을 확인했고 그대로 재사용합니다. 같은 기능의 재구현을 요청하는 것이 아닙니다.

| 필요한 내용 | 회신 요청 |
|---|---|
| 서버 접속 주소 | 3번 PC에서 접속할 서버 주소(IP 또는 호스트·포트)와 현재 실행 가능한 시간을 알려주세요. 실제 주소의 전달 경로도 안내해주세요. 다른 PC의 127.0.0.1을 팀 서버 주소로 사용하지 않습니다. |
| 직원·관리자 로그인 | 조회 검증에 사용할 직원·관리자 계정의 준비 여부와 전달 방법을 알려주세요. 기존 계정을 사용할 수 있으면 그 방법을, 아직 없으면 발급 담당·가능 시점을 회신해주세요. |
| 서버·MySQL 연결 상태 | 서버가 사용할 MySQL과 공통 로그인 테이블이 준비됐는지, 3번 PC에서 로그인할 수 있는지 알려주세요. 3번 클라이언트에 DB 비밀번호를 넣거나 DB 파일을 전달받는 방식은 사용하지 않습니다. |
| 아직 공유 서버를 쓸 수 없는 경우 | 사용 가능한 개발 환경·실행 안내와 준비가 필요한 항목·담당·가능 시점을 알려주세요. 1번 부재 중에는 기존 안내를 바탕으로 팀장과 실행 가능 범위만 확인하고, 미확정 공통 인증·DB 설정은 대신 변경하지 않습니다. |

**비밀번호·토큰·실제 .env·DB 덤프는 LOG/PR에 적거나 첨부하지 말고, 계정 정보는 팀이 정한 별도 전달 경로로 공유해주세요.** LOG에는 준비 여부·전달 방법·다음 담당만 남겨주세요.

## 2번 담당자에게 — 업무 조회 실행 준비

기존 `ITaskQueryService`, `HttpTaskQueryService`, `GetTasksAsync`/`GetTaskAsync`와 `GET /api/v1/tasks?scope=own|managed`, `GET /api/v1/tasks/{task_id}`는 확인했습니다. 기존 인터페이스·DTO 변경이나 조회 코드 재전달을 요청하는 것이 아닙니다. 기존 W3-01/03/04와 연결해 아래 실행 환경만 확인해주세요.

| 필요한 내용 | 회신 요청 |
|---|---|
| 업무 조회 활성화 | 1번과 정한 검증 서버에서 업무 조회 API가 활성화됐는지, 아직이면 명시적 개발 활성화의 담당·선행 조건·가능 시점을 알려주세요. 기본 off를 임의로 바꾸거나 공유 DB에 검토용 DDL을 자동 적용하지 않습니다. |
| 업무 테이블 준비 | 검증 환경에 조회에 필요한 업무·현재 배정·지정 관리자 관계가 준비됐는지, 사용할 기준 커밋과 실행 안내를 알려주세요. 정식 migration·공유 적용 승인 여부와 개발 환경 준비를 구분해주세요. |
| 내 결과물에서 확인할 업무 | 전달받을 로그인 계정에 현재 배정된 업무를 기존 등록·배정 기능으로 준비할 수 있는지 알려주세요. 목록·상세 대조에 사용할 업무와 기대 조회 범위를 확인하고 싶습니다. 업무가 없으면 빈 목록으로 확인합니다. |
| 관리자 조회 범위 | 관리자 본인 업무(own)와 해당 관리자로 지정된 업무(managed)를 구분해서 확인할 수 있는 계정·관계 준비 여부를 알려주세요. managed 조회 관계를 제출 승인 권한으로 사용하지 않습니다. |
| 수락·재작업의 현재 제한 | 최신 기록에서 수락·재작업은 읽기 전용 대상 확인이고 실제 상태 저장은 미연결임을 확인했습니다. 이번에는 확인 가능한 업무 조회 범위만 회신해주세요. 진행중 업무를 만들기 위해 DB 상태를 직접 바꾸거나 미구현 동작을 성공으로 표시하지 않습니다. |

**자동 샘플 업무·제출 이력 생성이나 DB 직접 수정을 요청하지 않습니다.** 사용자가 기존 기능으로 등록·배정한 업무를 조회하는 방식으로 확인합니다. 최초 제출·재제출·회차·판단·파일·이력 기능을 2번에게 대신 구현해 달라는 요청도 아닙니다.

## 3번이 환경 준비 후 확인할 항목

1. 직원·관리자 계정으로 공통 로그인하고 ReviewsControl에서 허용된 업무 목록을 조회합니다.
2. 업무를 바꿔 선택할 때 업무 번호·제목·담당자·상태·기간·설명이 해당 업무로 바뀌는지 확인합니다.
3. 빈 목록·조회 실패·권한 거절·로그아웃을 구분하고, 다른 업무를 선택한 뒤 이전 응답이 화면을 덮어쓰지 않는지 확인합니다.
4. 제출 회차·결과 설명·첨부·검토 의견의 현재 로컬 표시를 서버에서 가져온 기록으로 보고하지 않습니다. 실제 제출 이력·첨부·검토 권한 연결은 기존 W3 초안과 후속 계약에 따라 별도로 진행합니다.

반려완료 → 본인 재작업 시작 → 진행중 → 재제출 성공 → 제출완료 흐름과 최초 1차·성공한 재제출마다 +1차·업무상 회차 상한 없음은 유지합니다. 마감·검토자 지정·재배정 등 미합의 정책은 이번 실행 요청으로 확정하지 않습니다.
