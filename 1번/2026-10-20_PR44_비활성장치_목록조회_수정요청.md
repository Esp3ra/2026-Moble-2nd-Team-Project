## R44-01 [P2] 비활성 장치를 후보 목록에서 제외하기

위치: `RemoteWork.Server/remotework/features/enrollment/routes.py:51-53`.

한 관리자에게 정상 장치A와 비활성 장치B의 명시적 enrollment_device grant가 남아 있고 대상 회원/접속/키·프로필이 유효한 경우입니다. `eligible()`가 장치의 enabled를 거르지 않고 모든 grant에 `device_access()`를 호출합니다. B에서 `ENROLLMENT_UNAVAILABLE`409가 발생하여 목록 응답 전체가 중단되고, 정상 A도 클라이언트가 선택할 수 없습니다. 장치 폐기/비활성화에 따라 후보를 제외해야 하는 정상 운영 경로입니다. 관리자의 grant를 강제로 삭제하거나 정상 장치ID를 수동 입력해야만 우회하는 흐름으로 두지 않습니다.

**실제 결과:** 새 소유 MySQL8.2/RR, 활성 관리자/직원·공개 가상 키, A enabled=True/B enabled=False, 두 장치 모두 grant. `GET /api/v1/device-enrollments/eligible-devices?target_user_id=<활성직원ID>` → **409 ENROLLMENT_UNAVAILABLE**. 기대는200이며 목록에는 A만 있어야 합니다. 원본 회귀의 단일 장치 검사는 통과하지만 이 혼합 상태의 독립 회귀는1실패했습니다.

최소 재현은 제출본 `RemoteWork.Server/tests/test_device_enrollment.py`의 기존 `env,mutate,DID,KEYS,Device,grant_resource,ROOT`를 그대로 사용합니다. URL은 사용자 DB가 아니라 소유 전용 remote_work_test_ MySQL이어야 합니다.

```python
def test_disabled_device_does_not_hide_another_eligible_device(env):
    app, client, headers, ids, *_ = env
    disabled = '223e4567-e89b-42d3-a456-426614174000'
    app.config['ENROLLMENT_DEVICE_KEYS'][disabled] = KEYS.copy()
    def add_disabled(db):
        db.add(Device(device_id=disabled, display_name='Disabled synthetic device',
            enabled=False, key_id=KEYS['key_id'], key_epoch=1, minimum_slot=0,
            maximum_slot=299, capacity=300, candidate_slots_json='[7,8]'))
        grant_resource(db, ids['admin1'], 'enrollment_device', disabled)
    mutate(env, add_disabled)
    response = client.get(ROOT + '/eligible-devices?target_user_id=' +
                          str(ids['staff1']), headers=headers)
    assert response.status_code == 200, response.json  # actual409
    assert [d['device_id'] for d in response.json['data']['devices']] == [DID]
```

수정 방향: **후보 목록**에서는 비활성 장치를 먼저 제외하고, 남은 장치의 명시 grant·키/프로필과 대상/접속 검사를 유지합니다. `device_access()`의 쓰기용 거절을 전체적으로 완화하거나 예외를 모두 삼키지 않습니다. 발급/승인/완료에서는 비활성 장치409가 계속 필요하고, 대상 회원/관리자/접속 자체가 무효인 오류도 목록 성공으로 숨기지 않습니다.

재검증: 정상+비활성 grant 혼합→정상만200, 전부 비활성→빈 후보, 권한 없는 장치 비노출, 비활성 장치 직접 발급/승인/완료 거절, 현재 권한/접속/대상 검사의 유지. 수정 head를 올린 뒤 독립 재현과 기존 회귀를 다시 검토합니다. 협의/정책 회신용 새 문서PR은 요구하지 않으며 기존 코드PR44를 갱신하면 됩니다.
