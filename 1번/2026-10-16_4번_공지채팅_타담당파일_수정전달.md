# 4번 공지사항·채팅 작업의 타 담당 파일 수정 전달

작성: 4번 담당 · 수신: 1번 공통·통합 담당, 3번 결과물 담당 · 기록일: 2026-10-16

[1번 전달 기록](README.md) · [전체 기록](../README.md) · [2번 참고 양식](../2번/업무_구현검증.md#r006)

공지사항·채팅의 로컬 동작을 연결하면서 1번의 공통 메인 화면 2개 파일과 3번의 결과물 화면 1개 파일을 수정했다. 이 문서는 해당 담당자가 수정 이유와 실제 변경 범위를 검토할 수 있도록 전달하는 기록이다. 기능별 구현 책임을 1번에게 넘기는 요청은 아니다.

## 2. 요청과 착수 판단

사용자는 기존 프로젝트 구조 안의 코드만 골라 포크 alpha에 올리고 팀장 alpha로 PR을 보내도록 요청했다. 이어서 다른 팀원 담당 영역을 수정한 경우 LOG의 1번 폴더에 기록하고, LOG의 2번 문서 형식을 참고하도록 요청했다.

로컬 `2차 프로젝` 전체를 덮어쓰면 팀장 alpha의 최신 업무 조회 경계와 관리자 본인 결과물 구분이 이전 코드로 돌아갈 수 있었다. 따라서 4번의 `Features/Collaboration` 수정본을 옮기고, 공통·결과물 파일은 아래 필요한 변경만 별도로 반영했다. 로컬 폴더의 다른 담당 변경을 일괄 게시하지 않았다.

실제 추가한 공통 연결 코드는 다음과 같다.

```csharp
private readonly IChatService? chatService;

// MainForm 생성자의 디자인 모드 검사 이후
chatService = new InMemoryChatService(role == PreviewRole.Administrator
    ? new ChatParticipant("ADM-001", "이관리자", "운영관리팀")
    : new ChatParticipant("EMP-001", "김직원", "개발팀"));

// btnChat_Click
if (chatService is not null)
    ShowPage(new ChatControl(chatService), btnChat);
```

`IChatService`, `InMemoryChatService`, `ChatParticipant`는 4번의 Collaboration 안에 둔다. 메인 창은 저장소를 생성·전달하는 연결만 담당한다. 현재 저장소 수명은 메인 창 단위이며 메인 창을 닫으면 채팅 기록은 사라진다. 역할별 샘플 ID는 인증된 사용자 식별자나 서버 권한 근거가 아니다.

1번 공통 로그인·사용자·HTTP 코드는 별도 [PR #2](https://github.com/Esp3ra/2026-Moble-2nd-Team-Project/pull/2)에서 검토 중이다. 향후 통합 시 위 샘플 참여자 생성 위치를 실제 인증 사용자 문맥에 맞춰 조정해야 한다. PR #2의 공통 사용자·통신 인스턴스를 이 기록의 샘플 코드로 덮어쓰거나 4번 화면에서 임의로 구현하지 않는다. 비동기 종료·접속 교체 동작은 실제 공통 클라이언트와 연결한 뒤 별도로 검증한다.

## 7. 기존 검토에서 전달된 미완료 항목

[2번의 PR 검토 기록](../2번/PR_검토기록.md#r005)은 PR #1의 디자인팀 대상 필터 누락을 4번 범위로 보고했다. 작성 화면에서는 디자인팀을 선택할 수 있지만 조회 필터는 전체·전 직원·기획팀·개발팀만 있다. 이 문서 작성으로 해당 코드를 수정하지 않았으며, 앞선 58개 검증도 디자인팀 필터 완료를 보장하지 않는다. 4번이 후속 변경에서 처리·검증할 항목이다.

같은 문서의 R1~R3은 PR #2 공통 인증·통신에 대한 2번의 검토 결과다. 이 문서는 그 문제를 재현·수정한 기록이 아니며, 실제 후속 수정 여부는 1번의 최신 회신과 커밋으로 확인한다.

## 9. 앞으로의 타 담당 수정 기록 기준

사용자 요청에 따라 4번 작업 중 다른 팀원 담당 파일·인터페이스·공통 동작을 수정하면, 같은 시점에 LOG 브랜치의 `1번/YYYY-MM-DD_4번_주제_수정전달.md`로 전달 기록을 작성한다. `1번/README.md`와 LOG 루트 README의 목록도 갱신한다.

기록에는 원 담당·변경 파일과 메서드·수정 이유·변경 전후·보존 범위·기준 커밋/PR·실행한 검증·미실행 검증·미합의 항목을 구분한다. 양식은 LOG의 `2번/` 기록을 따른다. 문서에는 비밀번호·토큰·실제 .env·DB 데이터·로컬 개인 문서를 포함하지 않는다. 코드 변경은 alpha PR, 전달 문서는 LOG PR로 분리해 서로 링크한다.

이 문서는 전달·검토 요청이며 담당자의 합의·승인이나 코드 병합 완료를 대신하지 않는다.
