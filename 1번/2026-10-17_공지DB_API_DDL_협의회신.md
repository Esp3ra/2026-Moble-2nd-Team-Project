## N4-02~04 — 수용한 현재 API·모델의 정확한 범위

| 항목 | 현재 코드와 1번 기준 |
|---|---|
| PK/FK | notices.id INTEGER, author_id→users.id INTEGER·NULL 불가. ID0/범위 초과를 DB ID 바인딩 전에 거절. signed BIGINT 전환 요청 없음 |
| 데이터 | title String(200), content Text, target String(80), is_pinned Boolean, author snapshot String(80), created_at DateTime UTC, attachment_names_json Text. `(target, created_at)` 인덱스. ORM default가 raw SQL 서버 default를 뜻하지 않으므로 DDL에 실제 정책을 명시 |
| 목록 | GET `/api/v1/notices`, 선택 target=전 직원/기획팀/개발팀/디자인팀. page 기본1·상한1000000, limit 기본100·범위1..100, items/page/limit/total. pinned DESC·created_at DESC·id DESC. 업무 GET의 전체 목록 계약과 별도 |
| 상세 | GET `/api/v1/notices/{id}`, 로그인 필요. 1..2147483647의 정수 경로, 없거나 범위 밖이면404 NOTICE_NOT_FOUND. 음수/문자열 등 라우트 미매칭은 일반 HTTP_404일 수 있음 |
| 등록 | POST `/api/v1/notices`, admin만·201 data.notice. title/content trim 후 비어 있지 않음·최대200/5000, 대상4종·is_pinned bool. 작성자/시각은 서버 값. 허용 밖 body 필드 거절 |
| 첨부 | attachment_names는 최대20개의 파일명 메타데이터이며 실제 업로드/파일 서버가 아님. 파일명 최대255·경로/제어문자 등 차단. 후속 실제 파일은 3번·4번 경계와 보존/권한 별도 협의 |
| 삭제 | POST `/api/v1/notices/{id}/delete`, admin만·200 data.message. admin guard 뒤 공지 locking read+populate_existing. 같은 공지를 두 번 지우면 **첫200·다음404**, 성공 감사는1건. 자동 재시도 없음 |
| 오류 | 입력400 INVALID_INPUT, 인증401, 역할403, 미존재404 NOTICE_NOT_FOUND, 테이블 미준비503 NOTICE_SCHEMA_REQUIRED. 모든 DB 예외를404로 변환하지 않음. schema503의 로컬 CLI 안내는 공유 DB 실행 승인이 아님 |

잘못된/중복 query key를 거절하는 업무 GET 규약이 공지에도 구현됐다고 주장하지 않는다. 현재 공지 routes는 target/page/limit을 읽는 구현이며 추가 query 검증 강화는 별도 호환 변경으로 4번이 제안한다. auth/schema 검사 등 일반 DB 조회는 ID guard 전에 있을 수 있으므로 ‘범위 초과 시 SQL이 전혀 없다’고 표현하지 않는다.

## 검증·합의·게시 상태

이번 1번 실행 범위는 최신 요청·PR 본문/변경 파일/리뷰/댓글·소스·수정 회신의 정적 대조와 Markdown 경로/링크/표·N4 전 항목·게시 diff 검사다. 프로그램 테스트·Release 빌드·SQLite/MySQL 회귀·삭제 동시성·실제 HTTP·두 PC는 이번에 실행하지 않았다. #7 작성자의 SQLite74통과/16생략·MySQL 표적32 등의 보고는 [작성자 회신][reply]에 있는 **타 담당 실행 결과**이며 1번의 독립 검증으로 합산하지 않는다.

PR #7은 Draft·재검토 대기, #10/#11은 업로드 직전 확인에서 각각 LOG530f171·PR120d855로 병합됐다. 기존 #8/#9 및 이번 #10/#11의 문서 병합은 최신 수정 코드 승인과 구분한다. 이번 회신은 포크 LOG→원본 LOG의 문서 검토 대상으로 전달하며 새 코드 PR은 없다. 공동 항목은 4번·팀장·관련 담당 회신 대기, shared DB 적용/원본 코드 병합도 미완료다. 날짜별 요약은 로컬에서 팀장에게 전달할 자료로만 준비한다. 실제 게시 커밋·문서 PR은 [1번 목차](README.md)와 연결된 PR에서 확인한다.
