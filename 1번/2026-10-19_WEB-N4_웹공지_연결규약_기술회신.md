## 공통 파일에서 허용하는 최소 연결 범위

1. `remotework/web.py`: 기존 features 메뉴 중 notices 분기만 활성화 상태에 따라 공지 화면/503 안내로 연결. 기존 로그인·로그아웃·사용자·다른 메뉴를 재구현하지 않는다.
2. `features/registry.py`: 기존 notice gate 안에서 공지 웹 Blueprint 추가 등록만 수행. task/chat flag·현재 반환 목록을 보존하고 off 콜드프로세스에서 공지 모델 import를 새로 유발하지 않는다.
3. `templates/base.html`: 공지 메뉴명과 기본이 빈 기능별 extra_head 블록 추가. 같은 origin의 CSS/JS만 연결하고 보안 헤더·전역 CSRF·공유 인증을 변경하지 않는다. 사용자 내용을 HTML/JS 실행 코드로 렌더링하지 않는다.

위 밖의 공통 auth/db/models/app factory·공통 HTTP 변경이 필요하면 파일·이유·호환 영향부터 다시 협의한다. 4번 기능 routes/web/templates/static/test와 공통3파일의 구체 diff를 코드 PR에 분리해 보여 달라.

## 놓치지 않아야 할 구현·회귀 조건

- **CSRF와 인증의 처리 순서:** 현재 비API 쓰기는 before_request의 protect_forms를 먼저 거친다. CSRF가 없는 익명POST는400일 수 있다. 모든 미인증POST가 먼저 로그인302가 된다고 계약하지 않는다. 유효CSRF의 만료 접속·직원 관리자쓰기·현재 역할/활성 회수를 별도로 검사한다. API JSON에 웹 CSRF를 강제하거나 쿠키만으로 API를 인증하지 않는다.
- **조회와 선택:** 행 클릭은 선택만, 조회 버튼이 명시적으로 상세를 요청/표시한다는 사용자 기준 유지. 초기/작성 후 선택만으로 본문을 표시하지 않는다. 다른 필터/페이지·삭제/권한 변경 뒤 오래된 선택은 다시 검증한다. GET/행선택이 감사·확인 기록·업무 마감 상태를 저장하지 않는다.
- **정렬/페이지:** 웹20개 페이지는 웹 계약으로 분리하고 기존 API 기본100·필드/응답을 바꾸지 않는다. 정렬 열/방향은 서버 allowlist로 ORM 열을 고르고 query 문자열을 SQL 표현식으로 붙이지 않는다. 고정 우선과 안정적인 ID tie-breaker·필터/페이지 경계를 검증한다.
- **입력/XSS/CSP:** Jinja 자동 escape와 JS textContent를 사용하고 사용자 원문에 safe/innerHTML을 적용하지 않는다. 기존 CSP의 self 범위에서 외부 정적 파일을 사용하며 inline script 허용을 새로 열지 않는다. 파일명은 메타데이터, 실제 바이너리·PC 절대경로 저장 없음.
- **32KiB:** 제한은 파일/본문 각각이 아니라 요청 전체의 전송 바이트다. multipart boundary·csrf·필드 이름도 포함된다. 한글/이모지·메타데이터 최대 조합이413이면 저장하지 말고 안내한다. 전역 제한을 늘려 해결하지 않는다.
- **쓰기와 실패:** HTML303은 transaction context가 성공적으로 commit한 뒤 반환한다. 같은 공지 동시 삭제 첫200/API 후속404·감사1건, 역할/접속 회수 이후 쓰기 거절을 유지한다. 웹/API가 helper를 각각 호출해 두 번 저장하거나 helper 내부 commit 뒤 wrapper가 또 commit하지 않도록 검사한다. 전체 DB 예외를404·빈목록·정상303으로 변환하지 않는다.
- **fixture:** 제안한 DROP 순서 보완은 소유 테스트DB 안에서만 한다. 로컬에만 있는 팝업 자식 테이블을 이유로 제품 초기화에 DROP을 추가하거나 미합의 팝업 모델을 기본 import하지 않는다.
