# 장치 통신 검토용 테스트 벡터 — 제품 규약 확정 전

작성1번 · 전달5번 · 2026-10-19 · 상태: **MAC 바이트/인코딩 검토 자료, 상대 수용 대기**.

[회원·장치 기술 회신](2026-10-19_C10_C11_회원장치_수명연결_기술회신.md)의 후보 v1 바이트 규약을 대조하기 위한 가상 자료다. nonce/장치/시각/슬롯은 모두 가상이며 실제 등록/권한·만료·재사용 검사가 아니다. 아래 공개 시험 키는 **운영/장치에 설치하면 안 되는 알려진 테스트 값**이다. 실제PC 중계기는 이 키를 갖지 않는다. 방향별HKDF/최종필드·모델/상태는 협의 후 벡터를 보완한다.

wire envelope는 v/kind/device_id/key_id/payload_b64/mac_b64만 포함한다. 아래 fixture 바깥의 payload_utf8/public_test_key_hex/expected 길이는 설명 값이며 전송 필드가 아니다.

```text
M = ASCII("RW-ID-v1") || NUL || ASCII(kind) || NUL
  || ASCII(device_id) || NUL || ASCII(key_id) || NUL || ASCII(payload_b64)
MAC = HMAC-SHA256(공개 시험 키, M)
payload_b64 / mac_b64 = 패딩 없는 canonical base64url
```

## 재현과 이번 실행 범위

위 각 fixture를 JSON으로 복사한 뒤 다음 표준 라이브러리 코드로 기대 MAC을 대조할 수 있다. 디코더 검증/실제 제품 파서/DB 소비 상태를 이 예제로 대신하지 않는다.

```python
import base64, hashlib, hmac
e = fixture["envelope"]
m = ("RW-ID-v1\0" + e["kind"] + "\0" + e["device_id"] + "\0"
     + e["key_id"] + "\0" + e["payload_b64"]).encode("ascii")
mac = hmac.digest(bytes.fromhex(fixture["public_test_key_hex"]), m, "sha256")
actual = base64.urlsafe_b64encode(mac).rstrip(b"=").decode("ascii")
assert actual == e["mac_b64"]
assert len(m) == fixture["expected_mac_input_bytes"]
```

C# 대조는 Encoding.ASCII.GetBytes로 같은 M을 만들고 HMACSHA256.HashData 및 Convert.ToBase64String의 끝 '=' 제거·'+'→'-'·'/'→'_'로 같은 값을 확인했다. 고정시간 바이트 비교를 사용했다. C#검사기는 개발용 대조기이며 실제PC에 키를 배포하는 기능이 아니다.

이번 실제 실행: Python20검사(두 방향 원문/기대MAC·바이트/방향/key_id/키 변조·비정규base64url6종 및 RFC5869 A.1의PRK/OKM), .NET8 C#10검사(UTF8/base64url·MAC입력hex·MAC값·변경입력 거절)를 별도 실행했다. 공개 고정 키로 MAC 형식을 확인한 것이며 실제 장치 보안/전체 JSON스키마/서버단일소비·replay/만료/매핑·TLS·장치재시작·근태 수명 통합 검증이 아니다.

실행 명령은 로컬 전용 검증기 `python .local/coordination-round2-1019/vector_check.py`, `dotnet run --project .local/coordination-round2-1019/VectorCheck/VectorCheck.csproj -c Release -- .local/coordination-round2-1019/vectors.json`이며 제품/공통 모듈을 변경하지 않았다. 공개된 위 fixture로 기대 바이트/MAC을 독립 재현할 수 있다.

표준 근거: [RFC2104 HMAC](https://www.rfc-editor.org/rfc/rfc2104), [RFC5869 HKDF·공개 A.1 벡터](https://www.rfc-editor.org/rfc/rfc5869), [Python hmac](https://docs.python.org/3/library/hmac.html). 최종 규약/유효성은5번과 메시지·타입·상태안을 합의한 뒤 구현/재검토한다.
