## 실제 확인·보존한 구조

- `ITaskQueryService.GetTasksAsync(TaskListQuery, CancellationToken)`과 `GetTaskAsync(string, CancellationToken)`, `SourceDescription`.
- `TaskSummary`의 불투명 문자열 TaskId, 제목·담당자 표시명, 5개 논리 상태, DateOnly 시작일·마감일과 `TaskDetail.Description`.
- `TaskQueryFailure`: NotConfigured, AuthenticationExpired, Forbidden, NotFound, Unavailable.
- `TasksControl`의 조회 서비스 생성자 주입, 기본 UnconfiguredTaskQueryService, 명시적 TestDouble, 기존 테스트.

Features 전체와 기존 조회 테스트 60개 파일은 Git blob SHA까지 동일합니다. 기존 6개 시나리오·47개 검증도 재실행해 통과했습니다. 사용자 ID·역할·토큰을 조회 DTO에 추가하거나 테스트 대역을 기본 실제 조회로 바꾸지 않았습니다.

## 요청하신 6개 질문의 답변

| 질문 | 현재 답변·후속 결정 |
|---|---|
| 1. 실제 목록·상세 경로와 JSON | 아직 업무 API가 없습니다. registry의 BLUEPRINTS는 비어 있고 공통 인증·사용자·이력만 등록했습니다. INTEGRATION의 업무 코드는 연결 예시입니다. 1번·2번이 HTTP 메서드·경로·응답·오류를 합의한 뒤 2번이 업무 모델/API를 구현합니다. |
| 2. 전체·5개 상태·정렬·페이지 | 5개 화면 논리 상태와 기본 행동 전환은 유지합니다. C# enum의 이름/정수 순서를 DB·wire 값으로 확정하지 않습니다. 전체 필터의 wire 표현, 기본 정렬·페이지 메타를 합의해야 합니다. IReadOnlyList를 전체 조회로 볼지 페이지 모델로 확장할지도 결정합니다. |
| 3. Own/협업/Managed·직접 상세 | 아직 업무 배정·조직·상위 검토자 모델이 없습니다. g.user 기준 목록 SQL 조건과 직접 상세 접근 검사를 각각 구현해야 합니다. 공통 allow_admin=True는 grant 검사를 생략하므로 업무 범위 보장이 아닙니다. 별도 범위 조건 또는 allow_admin=False와 grant 동기화가 필요합니다. 공통 grant 거절은 403, 업무 존재를 404로 감추는 정책은 미합의입니다. |
| 4. DTO wire·NULL·현재 마감일 | 화면 모델은 그대로 보존했습니다. 실제 업무 PK·필드명·담당자 ID와 표시명·NULL·날짜 기준은 미합의입니다. 공통 기록 시각은 UTC ISO 8601이지만 DateOnly를 UTC 자정으로 임의 변환하지 않습니다. 연장 후 현재 적용 마감일도 함께 정해야 합니다. |
| 5. 공통 소스·호출·경로 결합 | 아래 실제 위치와 동작 예시를 공유합니다. ApiClient에는 서버 루트만 넣고 요청 경로는 api/v1 없는 상대 경로를 넘깁니다. 접두사는 한 번만 붙습니다. |
| 6. 담당과 연결 순서 | 1번은 공통 인증·통신·DB 연결·통합 지원, 2번은 업무 모델·조회 API·HTTP 어댑터, 3번은 제출·버전·승인/반려와 상태 연결을 담당하는 기준입니다. 관리 범위 정책은 팀장 포함 협의합니다. 계약→업무 DDL/API→기존 서비스 주입→권한·실제 HTTP/DB→두 PC/웹 순으로 연결합니다. |

실제 등록된 관리자 사용자 조회 예시입니다. 업무 API 계약 예시로 바꾸어 읽지 않습니다.

```csharp
var api = AppServices.Api;
var page = await api.GetAsync<PageResult<UserInfo>>(
    "users?page=1&limit=20", cancellationToken);
var signedInUser = api.CurrentUser;
```

`REMOTEWORK_API_URL=http://서버IP:5000/`처럼 서버 루트로 설정합니다. `/api/v1`이 붙은 주소는 현재 URL 검증이 거절합니다. 메서드에 `users...`를 넘기면 최종 `/api/v1/users...`가 됩니다. 후속 실제 조회 서비스의 생성자로 이 `api`를 전달하고 `TasksControl`의 서비스 주입 경계에서 연결하면 됩니다. 공유 인스턴스를 개별 화면이 Dispose하지 않습니다.

ApiException은 HTTP 상태·Code·Message를 제공하고, 호출자 취소는 OperationCanceledException으로 전달됩니다. 통신 실패·timeout은 StatusCode=0/Code 없음, JSON 형식 오류는 실제 HTTP 상태/Code 없음입니다. 기존 Unavailable에 이들을 포함할 수 있으며 더 나눠야 하면 공통 오류 구조를 협의합니다. 메시지 문구를 파싱하지 않습니다. 일반 경로의 HTTP_404를 곧바로 업무 미존재로 표시하지 않습니다. 정상 공통 JSON의 401은 공통 인증 컨텍스트를 비우고 메인 창이 재로그인을 안내합니다.
